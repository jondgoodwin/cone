Collection Types

Note: The library collection types are the collections package's List[T] and Dict[K, V] (keyed by any type that is Hash), OrderedDict[K, V] (the same, visiting in insertion order), Set[T], with String beside them (import collections use *;). A list or a dictionary is constructed with new, its first values after <-: new List[i32](100) <- fill 0 (a collection's contents). Each holds its elements in one block it gets from the C allocator through a raw pointer, not in an array reference. A borrow of an element (list[i], dict[key], s.view()) keeps a local collection loaned while it is used: it may be read, but a push, which may move every element, waits for the borrow's last use (see borrowed references). A mutable borrow (&mut list[i], or list.viewMut(), a &mut Array[T] of every element, and a String's s.viewMut() of its bytes) keeps it loaned entirely: until its last use the collection may be neither read nor changed any other way. Each declares ShapeChanging (a provisional name). Reached through a shared path, a &mut List parameter say, the same path is frozen the same way; but a push through another reference to the same collection is not seen yet, and leaves the borrow dangling (borrowed references). A list that a C function fills (the "ask how many, then fill" shape of Vulkan's queries) needs no unsafe code: list.resize(n, zero) makes it n copies of a value long (or drops the values past n), the C function is handed list.viewMut(), and list.truncate(written) cuts it to the count C wrote, finalizing the values it drops (a no-op when written is not less than its length). resize exists only where T copies; a list of values with finalizers is shortened with truncate. The array primitives are implemented as far as the next two pages say.

Note: A list is String's twin for any element. list.view() lends its elements as a &Array[T], the slice, and the list folds the methods of Array[T] in as its own (list.len is Array[T]'s). list.freeze() consumes the list and moves its block, shrunk to the elements it holds, into a So[Array[T]]: the elements are not copied, move types included, and the owner's death finalizes each of them once. A list that holds nothing makes a one-byte block, since the owner of an Array[T] always owns heap bytes (owned arrays).

Note: String is the growable string: a list of bytes and one spare byte, so its block always has a NUL after the text (which the length leaves out, rewritten by each change) for C, and a String that holds nothing has no block at all. s.view() lends it as a &str (the static empty literal when it holds nothing), and the String folds the methods of str in as its own (trimStart, isCharBoundary, slice and the ranges &s[a..b], the orderings < ...: The Methods of str), and == and the orderings compare its bytes with any other text, a literal, a &str, a So[str] or another String. A literal is copied into a String wherever one is wanted (imm s String = "core", names.push("core")). Text is a &str throughout: a &Array[u8] is bytes, and is not text until it says so (bytes as &str), though any &str is a &Array[u8] where bytes are wanted. Building: String.from(text), String.fromBytes(bytes) (a copy of bytes that are text, such as a buffer read from a file or a socket; nothing checks they are UTF-8, as bytes as &str does not), String.withCapacity(n), String.fromCStr(c) (a copy of a cstr's bytes, or of a raw pointer's, which is a panic if null) and String.join(parts, sep); appending: append(text) (also s <- text; Rust's push_str), appendBytes(bytes) (bytes that are text, unchecked like fromBytes), appendByte, appendInt, appendUInt and appendHex; editing: insert(i, text) (i between characters), remove(start, end) (the bytes from start up to end, both between characters), truncate(n), clear, replace(from, to), replaceByte, padStart, padEnd, lowerAscii and upperAscii; reading, in bytes, with &str text: equals, equalsIgnoreAsciiCase, and (folded in from str) compare, startsWith, endsWith, find, findFrom and contains; and copies of parts, which are Strings: sub, trim, lines and split. s.cstr() is its C string, the NUL already there, so nothing is copied; it is good until the String next changes, and a NUL inside the text is a panic, at the caller's line, since C would stop reading there. s.freeze() consumes the String and moves its block, shrunk to the text and its NUL, into a So[str]: the bytes are not copied.

Note: Dict[K, V] is a SwissTable: an open-addressed table with a control byte for each bucket (empty, removed, or the top 7 bits of the key's hash), read eight at a time as one 64-bit word, so a lookup compares a key only in a bucket whose tag matches; it holds up to 7/8 of its buckets, and doubles when full. Its keys are any type that is Hash: integers and bool, a String, a pool.Ref[T], a struct that declares is Hash (the compiler supplies its hash from its fields); a float key is refused. A key moves in and the dictionary owns it. It is unordered: each dictionary keeps a seed of its own, the process's random one by default, so keys(), values() and entries() (cursors, each next() giving an Option of a borrow, the dictionary loaned while one is used) visit in a different order on every run, and a program sorts, or looks a key up, rather than rely on it. Dict[K, V].deterministic() fixes the seed, and then the same keys inserted in the same order are visited in the same order on every run; Dict[K, V].withSeed(n) takes one of your own. Lookups take a &K: get(&k) is an Option of a borrow of the value, getMut a mutable one, getCopy an Option of a copy (only where the value copies, which is the lookup that works through a shared Rc[mut, Dict[K, V]]), contains, remove (the value moved out, the key finalized), d[&k] and &mut d[&k] (a panic for a key it does not hold), insert(k, v) (when it replaced an entry, finalizing the old key, an Option holding the old value moved out to the caller, as Rust's does, and None for a new key; the value dies with the caller's binding, or at the end of a statement that ignores it; d <- k: v ignores it), getOrInsert(k, v) (a mutable borrow of the value held, or else v moved in, with one search: *counts.getOrInsert(word, 0) += 1), clear, len and capacity (the entries it holds before it grows). A Dict[String, V], a Dict[So[str], V] or a Dict[Rc[str], V] (an owner of text is Hash, an immutable key with no spare capacity; a literal given to insert is copied into the owner) also takes the key as the body it lends or holds, a &str (d.contains("core")), for every one of these lookups: a literal, a view (s.view(), a slice of text), a So[str] and an Rc[str] are each lent as a &str, so none builds a String to ask. They find the key they equal because a str, a String and a literal feed a hasher the same bytes (str has a hash of its own) and == compares the bytes. A d["sdl"] of a key it does not hold is a panic that names the key; one by a &K does not. A &Array[u8] is not text until it says so: bytes as &str.

Note: OrderedDict[K, V] is a Dict that visits in the order of insertion, on every run and under every seed, which is what a program wants to print, write out as a file, or replay (a JSON object, a configuration, HTTP headers). It has the same methods under the same names, including the &str lookups of an OrderedDict[String, V] and the cursors keys(), values() and entries(), and the same seeds. Its layout is Python's compact dict and Rust's IndexMap: a dense array of (hash, key, value) in insertion order, which the cursors walk front to back, and beside it an index with the same control bytes and eight-at-a-time probe as Dict's, holding for each bucket a u32 position in the array, so a table holds fewer than 232 entries. A lookup is one memory access slower than Dict's; iteration is faster, with no empty buckets to skip. Inserting a key it holds replaces that entry where it stands; a key put back after a remove goes to the end. remove keeps the order: every later entry moves down one place, so it costs the entries after the one removed (IndexMap's shift_remove). swapRemove(&k) is O(1) but moves the last entry into the hole, which breaks the order. If you mostly look keys up and rarely iterate, Dict is the faster choice.

Note: Set[T] is a set of any type that is Hash: a Dict whose values take no bytes, so it has the dictionary's table, seed and unordered visiting. insert(x) answers whether x was new (a held element stays, and the item given dies), contains(&x), remove(&x) (true when it was held), clear, len, isEmpty, capacity, deterministic() and withSeed(n); items() is a cursor over borrows of the elements. A Set[String] takes an element as the &str a String lends (s.contains("core")). It has no union or intersection yet.

Note: Deque[T] is a double-ended queue, a growable ring buffer (Rust's VecDeque): its values are in one block, as a circle, the first at a slot that moves, so push and pop at the back and pushFront and popFront at the front are all O(1), where a List can take a value off its front only by moving every other one. peek() and peekFront() are an Option of a borrow of the last and the first value, get(i) the same of position i counted from the front (None past the end), d[i] and &mut d[i] borrow it (a panic past the end), and items() is a cursor over borrows from the front to the back. A full block is replaced by one twice the size (4, 8, 16, ...), the values moved in order with the first in slot 0; it never shrinks. reserve(n), capacity, clear (finalizing front to back, keeping the block), len, isEmpty and new Deque[T](n), a block of exactly n slots, are a list's. Its values may wrap round the block's end, so it has no view(): read them by position or with the cursor.

Note: List also has peek() (an Option of a borrow of the last value) and get(i) (the same for position i, None past the end), which do not panic.

Note: The collections package also declares five small traits, one for each thing a collection can do, so that a function asks for exactly the ability it uses; each is met structurally (Traits), by having the methods, so none of the collections declares one. Collection (len, isEmpty: List, Deque, String, Dict, OrderedDict, Set); Indexed[T] (get(i): List, Deque); Stack[T] (push and pop at the back, peek: List, Deque); Queue[T] (push at the back, popFront: Deque); Map[K, V] (get, insert, remove, contains by a &K: Dict, OrderedDict). A function asks for one as a static bound (A generic trait as a constraint), fn drain[S Stack[i64]](s &mut S), fn drain[T, S Stack[T]](s &mut S) or fn drain[T, S](s &mut S) where S is Stack[T], called with &mut list or &mut deque; the bound is decided where the function is called, so the call is to the type's own methods. A trait is given all its type arguments ([S Stack] is refused), while Collection, which has none, is written alone, fn count[C Collection](c &C). The other form is a virtual reference, fn drain(s &<mut Stack[i64]), which takes the same arguments through one compiled function and a table of methods, for a value whose type is not known where the function is compiled; every trait works either way. Map's insert answers the old value, an Option (None for a new key). A Set is not covered by a trait yet; its insert answers whether the element was new.

A collection type holds some number of values (elements) that are all the same type. The standard library offers a number of versatile collection types, such as List, Deque, Dict, OrderedDict and Set.

All such collection types are built on top of the array primitive types, whose elements are co-located in memory and are individually accessed using an integer index:

  • Array types. An array has a statically known size.
  • Array reference types. An array reference, a slice, is a borrowed view of some runtime-determined number of elements of the same type: all or some of the elements of an array, or of a collection. It owns none of them. An array whose length is chosen at runtime is a collection.
