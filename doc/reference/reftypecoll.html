Collection Types

Note: The library collection types this page names are not implemented; no Vec or HashMap name resolves. A first collections package offers List[T], String and Dict[K, V] (keyed by String only), whose names are not settled. A list or a dictionary is constructed with new, its first values after <-: new List[i32](100) <- fill 0 (a collection's contents). Each holds its elements in one block it gets from the C allocator through a raw pointer, not in an array reference. A borrow of an element (list[i], dict[key], s.view()) keeps a local collection loaned while it is used: it may be read, but a push, which may move every element, waits for the borrow's last use (see borrowed references). Each declares ShapeChanging (a provisional name), which is to refuse such a borrow through a shared path, a &mut List parameter say; that check is not built, and a push through another reference to the same collection leaves the borrow dangling. The array primitives are implemented as far as the next two pages say.

A collection type holds some number of values (elements) that are all the same type. The standard library offers a number of versatile collection types, such as Vec and HashMap.

All such collection types are built on top of the array primitive types, whose elements are co-located in memory and are individually accessed using an integer index:

  • Array types. An array has a statically known size.
  • Array reference types. An array reference, a slice, is a borrowed view of some runtime-determined number of elements of the same type: all or some of the elements of an array, or of a collection. It owns none of them. An array whose length is chosen at runtime is a collection.
