Pattern Matching

Note: A basic match capability is implemented: equivalence patterns, with or without ==, comparison patterns, range patterns, or between patterns, if guards, bound pattern matching, variants named bare, and 'else'. A match must cover every value it can be shown to cover, or end in else (Covering every value), and match a, b matches several values at once (Several values). Not implemented: partial matches and first-class patterns, beyond binding a variable to a variant. A condition written where a pattern is expected, such as case not b or case n > 3, is refused: the comparison case >3 and an if guard say it. The form of the matched value decides what a match takes (What a match takes), and a pattern names only the variant, the matched value supplying the reference it is (Variant type partial matches). A binding through a mut or ro reference is followed by the collection rule: allowed, and refused only if something could change the variant while it is used (an owned Rc is not narrowed this way yet). A struct's partial pattern is written with its fields in square brackets (Point[0., _]), and a variant's as a variant is constructed, in square brackets (SomeInt[<0]): that is the current spelling, and how a match pattern spells a type or a construction is an open design question, as is how a variant is constructed (Enums).

As with if, pattern matching is about deciding which code path to perform. Its approach is to match a single value against multiple patterns. The code block associated with the first matching pattern is performed.

Let's illustrate this with a simple (but mathematically unusual) example:

fn power(n i32, pow i32) i32 {
  match pow {
    case ==0 { 1; }
    case ==1 { n; }
    case ==2 { n * n; }
    else { -1; }
  }
}

This example calculates its value differently based on the value of pow. If pow is zero, we return 1. If pow is 1, we return n. If pow is two, we return n squared. Finally, if pow is any other value, we return -1.

The structure of this form of pattern matching is straightforward:

  • Any normal expression can be used after match. This expression's evaluated value is what patterns are matched with. If desired, an assignment expression can be used here to capture this matchee value for later use in matched code blocks.
  • Any number of pattern blocks may follow. Each is comprised of the case keyword, followed by a match pattern, which is followed by a block. When a match pattern matches, the evaluated value of its block is the match's value
  • Using the else pattern will always match any value. If specified, it must be the last pattern used.

Covering every value

Every match must cover the values it matches, statement or value alike, or end in else. The compiler counts what simple, clear logic can count, and asks for an else wherever it cannot:

  • A match on an enum is covered when every variant has a case. A case names a variant alone (case Circle), binds it (case imm c Circle) or ors several (case Rect or Dot); each counts toward every variant it names.
  • A match on a bool is covered by case true and case false.
  • A match on several values is covered when every combination of its columns is (below).
  • Anything else — numbers, characters, text, floats, a comparison, a range, a value held in a variable, a guarded case — matches some values, and which only running says. The compiler does not try to prove it covers them all. End such a match with else, which may say only that no other value can happen: else {}.

A match that is not covered is an error that names what is missing, so a statement match that handles some variants needs else {} to say the rest need no action. The opposite is an error too: a case that can never run, because the cases before it match every value it matches (a variant named twice, a case after the cases cover everything), and an else after cases that already cover everything. Open traits never count: a match on a trait that other modules may add structs to needs its else.

fn name(s &imm Shape) i32 {
  match s {
    case imm c Circle { c.radius; }
    case Rect or Dot { 0; }          // every variant: no else
  }
}
fn side(n i32) i32 {
  match n {
    case 0 { 1; }
    case 1 ..< 10 { 2; }
    else { 3; }                       // numbers cannot be counted
  }
}

A versatile range of patterns are supported, able to match wholly to specified values, partially, or using a first-class pattern. Pattern matching also supports de-structuring portions of the original value into bound variables.

What a match takes

The form of the expression after match decides what the match does with it, and a bound if, if imm c Circle = s, reads its value the same way.

  • A place — a variable, a field of one, a dereference, an element at a name or a literal, match r — is matched as the value it holds. Every test reads it where it stands and takes nothing, so a match that only tests moves no resource away, and r is whole after it. An arm that binds is the one that takes: the binding holds the payload by value, a copy of a copy type, or a move of one that owns, which consumes r on the paths that reach that arm. A mut binding changes what the arm took and never r.
  • A borrow — match &r, &imm r, &mut r, &uni r — binds a reference of that kind into r, which stays frozen to the match for as long as the bindings are used. That is how a match changes r: match &mut r.
  • Any other value — a call, match f() — is a temporary the match owns: it is made once, every pattern reads it, and it is finalized as the match ends.

A match with a bound if guard (case imm x Some if x > 0) holds the value it matches as a temporary does, since the guard reads the binding before the arm is chosen.

Whole Value Matches

These patterns involve straightforward comparisons between the matchee value and one or more pattern values.

Equivalence

The simplest form of matching uses a value as the pattern. This can be a constant value (as above) or any expression that evaluates to some value, for example:

match val {
  case ==anotherval.len { 4; }
  else { 0; }
}

The type of the pattern value must match the type of the matchee value. An equivalence match is performed between these values as if using the '==' operator.

The == may be left out: a value on its own is an equivalence pattern, so case 0 means case ==0, case true means case ==true, and a named constant, case LIMIT, is compared the same way. A name on its own that is a variant of the matched value's enum is that variant's pattern instead: case Circle on a Shape means case is Circle (see Variant type partial matches).

match val {
  case 0 { 4; }
  case LIMIT { 5; }
  else { 0; }
}

A string matched against a slice of bytes is compared as two slices are, element by element, so case "box" holds when the slice holds exactly those three bytes:

match word {
  case "box" { 1; }
  case "ball" or "bat" { 2; }
  else { 0; }
}

Note: an equivalence pattern counts toward covering every value only as the literal true or false on a bool, with or without ==. A variant named on its own counts, as case is does. A number, a character, a string or a named constant does not: the match ends in else.

Comparisons

Comparison patterns make use of the comparison operators (including !=). The left hand value is not specified, as it is understood to be the match value:

match n {
  case <0 { -1; }
  case >0 { 1; }
  else { 0; }
}

A negative value after < needs a space between them, as in case < -1: <- is the append operator.

Range pattern

The range pattern checks whether the matchee value lies within a specified range. This is specified by placing either the .. or ..< range operator between two expressions. The two mean what they do in a number range of each and in a subslice: .. includes its end and ..< stops before it. Anything that can be ordered, characters among them, can be matched against a range:

match n {
  case 0 ..< 3 { 1; } // matches 0, 1, or 2 (but not 3)
  case 3 .. 6 { 2; }  // matches 3, 4, 5 or 6 inclusively
}

match c {
  case 'a' .. 'z' { 1; }  // a lower case letter
  case 'A' ..< 'Z' { 2; } // an upper case letter but Z
  else { 0; }
}

A range pattern is not a step: by belongs to each alone.

Pattern Expressions

Before continuing on to talk about partial pattern matching, let's introduce ways to enhance the match patterns already described as part of a more comprehensive pattern expression.

Multiple patterns

It is possible to list more than one possible pattern to match, using or between each pattern:

match n {
  case 2 or 3 or 5 or 7 { 2; }
  case -6 or -1..1 or 6 { 1; }
  else { 0; }
}

Each pattern joined by or may be any of the whole value patterns, or an is test. A pattern that binds a variable stands alone.

Several values

Several values can be matched at once by writing them after match, separated by commas. No tuple is made: the commas are all it takes. Each case then gives one pattern for each value, separated by commas, and matches when every value matches its pattern. The values are evaluated once each, left to right, before any pattern is tried. _ is the pattern that takes any value; it belongs to this form alone (a match of one value ends in else):

match key, value {
  case 0, _ { 0; }
  case _, 0 { 1; }
  else { 2; }
}

match state, byte {
  case Start, 'G' { 1; }
  case Start, _ { 0; }
  case Done, _ { 2; }
}

A pattern of a column is any pattern of a single value, or included (case Start or Done, 'G'), followed by one if guard for the case. A pattern of a column does not bind a variable. The second match above (where state is an enum of just Start and Done) has no else: it is covered, because every combination of the variants is. The compiler counts the combinations of the values it can count (variants and bools), and a case that tests a number or a character in a column counts toward none. The first Start case tests a character, so it is case Start, _ that covers Start; without it the match would need its else.

if Guards

An 'if' clause may be specified following all patterns as an additional guard. The condition expression after the 'if' must evaluate to true in order for the match to take place.

match nbr {
  case ==4 if cnt > 0 { 0; } // matches only if nbr==4 and cnt>0
  case ==4 { 1; } // matches when nbr==4 and cnt<=0
  else { 2; }  // matches when nbr != 4
}

A guard may follow a pattern that binds a variable, and may use it:

match opt {
  case imm x Some if x > 0 { x; }
  case imm x Some { 0; }
  case is None { -1; }
}

Because a guard can fail, a case with a guard does not account for its variant when deciding whether a match covers every value. Above, the unguarded Some case does.

Partial matches

When dealing with a composite data structure, partial matching supports value or type matching on selected parts of that data. A partial match pattern mimics the type structure of the data we are matching against, specifying match patterns for the value or type of particular substructural elements. It also supports "destructuring", binding variables to these or other substructural elements.

Partial match patterns begin with the is operator. Additional specifics of the pattern vary by type.

Collection partial matches

The simplest partial match checks whether an array (or array reference) begins with certain elements:

match name {
  case is "Judy" { judy; } // Matches if name string begins with "Judy"
  case is "Frank" { frank; }
  else { noone; }
}

Alternatively, one can specify matching patterns for the first few elements:

match numbers {
  case is [1, _] { 1; }
  case is [_, 1] { 2; }
  case is [<=0, <=0] { 3; }
  else { 4; }
}

Struct partial matches

A matching pattern may be created for specific named fields:

match points {
  case is Point[0., _] { 1; }
  case is Point[_, 0.] { 2; }
  case is Point[<0., &lt=0.] { 3; }
  else { 4; }
}

Any unspecified fields in a struct pattern are assumed to match.

Variant type partial matches

An variant pattern typically just matches against each option's variant type, binding to a variable:

match oddval {
  case imm intval SomeInt { intval; }
  case imm point PointStruct { i32.from(point.x * point.y); }
  case is None { 0; }
}

A binding gets what the variant holds. A variant declared as a type (SomeInt(i32);, see Variant forms) holds that type itself, so intval above is the i32, with no field to name: Some, Ok and Error are declared this way. Bound by value, it is a copy of the i32, or, when what it holds moves, a move of it out of the matched value, which is then finalized without it; a mut binding changes the copy and not the matched value. Bound through a reference (case imm n SomeInt on a reference to the enum), it is a reference of the same permission to what the variant holds, an &i32 here. A variant declared as a struct binds the struct, whose tag is never a visible field.

A variant is a name of its enum (see Naming a variant), and a pattern names it bare with no use: the match already knows which enum the value belongs to. This is true of every pattern on a value — a case, a bound if or elif, and an is test — and it looks through a reference, so case imm c Circle on a &Shape names Shape.Circle.

A pattern names only the variant. The matched value supplies the rest: the type arguments, and, where it is a reference, the kind of reference, its region and its permission. On a &imm Shape, case imm c Circle binds an &imm Circle; on a &mut Shape (a borrow made at the match), an &mut Circle; on an Rc[mut, Shape], an Rc[mut, Circle]; on a Shape, a Circle. A test with no binding, case Circle or s is Circle, asks only whether the value is that variant. A pattern may still be written as the reference, case imm c &Circle, which then checks that the matched value is one: it is an error where the value is no reference, or is in another region, or has a weaker permission than the pattern asks for. A managed reference is never spelled in a pattern, and the older +Rc-mut Circle is refused.

A binding through a reference points into the variant, and follows the collection rule. Through a reference, c is a reference into the value's payload, and a change of variant would have it read the payload as the wrong type. It is a borrow into the enum, as an element is a borrow into a list (Borrowed references), so it is allowed through any reference, and refused only if something could change which variant the enum holds while c is still to be used:

  • the enum stored over whole (*s = Shape.Rect(1, 2, 3)) or swapped, through the same name or another;
  • a call handed the enum, or anything that could reach it, whose body (or what it calls) does either, or whose body the compiler cannot read.

Writing a field within the variant is not a change, whether through c or through the enum's name, and neither is a field every variant has (s.kind = 9), nor reading the enum, nor a call that only reads it. The refusal is reported at the change, and says where c is used again; a change after its last use is fine, which is how a state machine moves to its next state. A borrow of a local made where it is matched needs no question: the borrow freezes the local (Freezing access to the source of a borrow) until the binding's last use, and a uni, imm or mut1 reference has no other name to change it. A value owned by an Rc, another owner of the same value, is not narrowed this way yet: match a borrow of it. An is test binds nothing, and narrows through any reference.

fn grow(s &mut Shape) {
  match s {
    case mut c Circle {c.radius = 2;}   // Ok: nothing changes the variant while c is used
    else {}
  }
}
fn restart(s &mut Shape, t &mut Shape) i32 {
  match s {
    case mut c Circle {
      c.radius = 2;       // Ok: writing a field within the variant
      *t = Shape.Rect(1, 2, 3);   // Error: t may be another name for s, and c is used again
      c.radius;
    }
    else {0;}
  }
}
fn step(m &mut Machine) {
  match &mut m.state {
    case mut c Circle {
      c.radius = c.radius + 1;
      m.state = Shape.Rect(1, 2, 3);  // Ok: c is not used again
    }
    else {}
  }
}

The matched value's enum is asked first. A bare name in a pattern means that enum's variant whenever the enum has one of that name, whatever the name means elsewhere in the module, so a use of another enum with a Red does not change what case is Red means on a Lamp. Only a name the enum has no variant of is looked up as any other name is. A qualified pattern, case is Colors.Red, is taken as written; and a variant named through its enum alone, case Colors.Red, means case is Colors.Red, as the variant bare does.

The value supplies a generic variant's type arguments. On an Option[i32], case imm s Some means Some[i32]. Arguments may still be written where the name is in scope, as Some[i32] always is. Written on a variant that is in scope only because the matched enum has it, they are an error that says to drop them or to name the variant through its enum.

A struct variant bound by value is the value the arm took, under its variant's name, not a second copy of it. The arm takes the matched value into a variable of its own (a move of one that owns, which consumes a matched place on the paths to that arm), and when the arm ends it is finalized once, as the variant it is. Moving the bound variable, or handing it back as the case's value, moves that value. A bound variable declared mut changes that value, not a matched place: assigning over it, or over one of its fields, finalizes what is replaced, and a value swapped out of it with <=> leaves what was swapped in to be finalized with it. A match on a call, or with a bound guard, holds the matched value itself for the whole match and finalizes it as the match ends, whichever case ran.

Note: a bound variable moved, on every path or only some, and then assigned over leaves a value unfinalized: what it was given, or, where it was not moved, what it held.

If desired, pattern matching and binding can also be applied to the internal value(s):

match oddval {
  case imm intval = SomeInt[<0] { -intval; }
  case imm intval = SomeInt { intval; }
  case is PointStruct[x=_, y=_] { i32.from(x * y); }
  case is None { 0; }
}

First-class patterns

Whole and partial matching patterns handle many situations, but not all. First-class patterns make it possible to support more sophisticated matching algorithms. Such algorithms are implemented in a callable function or method that returns true for a successful match.

Use of a first-class pattern is signaled using the using keyword. The matchee value is implicitly included as part of the call (essentially, the first parameter for a function and the second for a method call):

match n {
  case using isPrime() { 0; } // invokes isPrime(n)
  case using isOdd() { 1; } // invokes isOdd(n)
  else { 2; }
}

This technique can be quite powerful, as it makes it possible to support a broad range of complex pattern matching strategies, such as regular expressions, parsing, etc. A first-class pattern can be an object with state that changes as a result of a successful match. As part of the match, data can be extracted from the matchee value and preserved for later use by the match block.

Note: A first class pattern can also be applied to any arbitrary value as part of an if statement:

if isOdd(n) { ++nbr; }
