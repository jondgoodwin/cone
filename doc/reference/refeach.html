Each and Iteration

Note: Not built yet: closure iterators, and a source that runs its own loop around the body of an each.

each makes it easier than while to iterate over a sequence of values. For example, here's the factorial function using each:

fn fact(n i32) i32 {
  mut result = 1;
  each x in 2 .. n {
    result *= x;
  }
  result;
}

Effectively this each statement binds the variable x to each iterated value from 2 through n, each time performing the loop's inner block.

As this example shows, the each statement has a simple structure:

  • One or more variables to be bound to values produced by the iterator. These variables are local to the each block and cannot be accessed outside that scope. Every pass binds new ones, and the block cannot change them: counting by hand is a while. A write to one is refused, and the message says how to change the items in place instead: walk src.mutItems().
  • An iterator that produces different value(s) on each iteration of the loop. The iterator follows in.
  • A block containing the logic to be performed on each iteration.

break and continue

break and continue statements may be used within an each block to stop or re-start the loop. Either may name a loop's label, to leave or re-start an outer one, and return leaves the function. Each of the three may end with an if and a condition, as continue if x % 2 == 0; does (While, Break and Continue).

Skipping items: if

An if and a condition after the source is a filter: the items for which the condition is false are skipped, as if the block began with if !cond { continue; }. It reads the loop's variables, and works for every kind of source below, ranges included:

each x in 0 ..< 10 if x % 2 == 0 {      // 0 2 4 6 8
}
each name in names if name.len > 3 {   // a List[String]
}
each key, value in ages if value > 18 {
}
each x in 100 .. 0 by -10 if x != 50 {
}

A loop that gives a value: else

A loop that is searching for something has two ways to end: it finds it and leaves with break, or it runs out of items. An else after the loop's block says what the loop is worth when it runs out, and with one the whole each is an expression whose value is the break's or the else's:

fn firstBig(list &List[i32], limit i32) i32 {
  each x in list {
    if x > limit { break *x; }
  } else {
    -1;              // nothing was big enough
  }
}

imm total = each x in 1 .. 100 {
  if x * x > 500 { break x; }
} else {
  0;
};

The value is of one type, whichever way the loop ends. The else block is an ordinary block (its last expression is the value, and it may do other work first), run only when the items run out; a break skips it. It stands outside the loop: the loop's variables are not in view, and a break or continue in it belongs to the loop around. It may end in a return instead, which gives the loop no value (else { return -1; }). An each with an else may also be a statement; a break that gives no value is then fine, and the else is run for what it does. An each without an else is a statement only. while with a condition does the same (While).

Building a collection: each inside <-

An each may stand in the list after the append operator (Operator Methods), beside values, of, fill and pairs. With only a source it drains it: every item is appended. With variables it is the loop's own header, including the if filter, and a yield in the place of a block says what each pass appends:

imm copy = new List[i32] <- each other;                     // every item of other
imm big = new List[i32] <- each x in other if x > 9 yield *x;
imm squares = new List[i32] <- each i in 1 .. 5 yield i * i;    // 1 4 9 16 25
imm index = new Dict[i32, str] <- each p in people yield p.id: p.name;
xs <- 0, each x in other yield x + 1, 99;               // in the middle of a list
imm tens = new List[i32] <- each other.iter().filter(x => *x > 2).map(x => *x * 10);   // a chain

This yield belongs to the entry: it is not a generator's, which is a statement of its own, so a generator may build a list this way and then hand values to its caller. Two or more variables unpack a tuple item as they do in a loop, and yield k: v appends a pair to a collection that takes a key and a value. The items an each gives of a collection are borrows, so a drain appends a copy of each (a type that moves is not copied: drain a source that hands its items over, each other.drain()), and a yield writes the * itself where it wants the value. The list being appended to cannot be the source: xs <- each xs is refused, as pushing to a list while a loop walks it is. An array's contents cannot hold an each, as its size is fixed.

The source may be a chain of adapters, in the bare form or after in in the header form: the chain is a cursor, and the entry walks it as any other, one loop. A chain that starts at a list's iter() hands out borrows, so the items are copied as from the list itself; a chain whose closure makes the value (map(s => String.from(s.view()))) hands the value over; and one that starts at drain() moves the items out of the list, those a filter rejects are dropped, and the list is left empty:

imm lengths = new List[usize] <- each names.drain().map(s => s.len);      // names is left empty
imm kept = new List[i32] <- each v in xs.iter().map(x => *x * 2) if v > 6 yield v + 1;
imm squares = new Dict[i32, i32] <- each k, v in xs.iter().map(x => (*x, *x * *x)) yield k: v;

A chain that starts at the list being appended to is refused as xs <- each xs is (xs <- each xs.iter().map(f), and with drain()). A chain whose closure reads the list while it grows (its len, an item's value) is allowed. A dictionary takes pairs by yield k: v in the header form; the bare form new Dict[K, V] <- each pairs is not built for any source. new List[T] <- parallel each chain is refused: a chain cannot be split (on its own page).

Iterators

each supports several ways to iterate over a sequence of values:

  • Number range, for simple arithmetic progressions.
  • Array, slice or list, to work with individual elements.
  • Cursor, something with a next method, and anything that gives one. A generator is a cursor.
  • Closure, to deal with algorithmically-generated values (not built yet).

Number Range Iterator

As the above example shows, a range is written with a range operator between its first and last numbers, and iterates successively over integers or floating point numbers. a .. b runs through b: it includes it. a ..< b stops before b. Iteration begins with the first number and then increments by 1. Expressions may be used in place of literal numbers, if desired. The same two operators make a range pattern and a subslice.

each x in 3 .. 7 {      // iterates:  3 4 5 6 7
}
each x in 3 ..< 7 {     // iterates:  3 4 5 6
}

A range never guesses a direction: one that starts past its end is empty, so 6 .. 2 runs no pass. To iterate backwards, count by a negative step:

each x in 6 ..< 1 by -1 {  // iterates:  6 5 4 3 2
}

A step value may be specified after by. Instead of incrementing by 1, the step value specifies how much to add to the iterated number each time, and its sign says which way the range runs. A step of zero runs no pass:

mut sum = 0;
each x in 0 .. 10 by 2 { // iterates: 0, 2, 4, 6, 8, 10
  sum += x;
}

A range counting down takes a negative step value. Iteration stops as soon as a step moves the number away from the end rather than toward it, which is also what a step past the largest (or smallest) value the number's type can hold amounts to:

each x in 10 .. 0 by -2 {      // iterates: 10, 8, 6, 4, 2, 0
}
each x in 250u8 .. 255 by 2 {  // iterates: 250, 252, 254
}

The end is read once, before the first pass, so an end that changes inside the body (0 ..< n while the body adds to n) does not move the range; a loop that needs the end read afresh is a while. A step that is not a literal (by dx) is read once too, and the sign it has then decides whether the range counts up or down. A fractional step is not added up: the number of a pass is the first value plus the count of steps taken times the step, so no rounding builds up in it. 0.0 .. 1.0 by 0.1 takes eleven passes, the last of them exactly 1.0, in f32 and f64 alike.

A range gives one variable. The loop steps a counter of its own and each pass's variable holds the number, so writing to the variable is refused. A loop that steers its count by hand is a while.

Array, Slice and List Iterators

each can be used to iterate through every element of an array, a slice or a list, one at a time. The variable is a borrow of the element (the elements themselves stay where they are, and the list is still whole afterwards). A borrowed number needs no * in an expression: it is read through on either side of an operator (x + total, total + x), on the right of a compound assignment (sum += x) and in a comparison (x > 1, or x == y for two borrows, which compares the values), and so is any value that copies freely: a bool, a char, a plain struct (Implicit De-referencing). The * is written where the value itself is wanted: a copy of the item (imm y = *x), a value handed to a function, a break or yield, or a store through a &mut:

mut sum = 0;
each x in [4, 3, 8, 2] {
  sum += x;
}

mut chars = 0usize;
each name in names {      // a List[String]: name is a &String
  chars += name.len;
}

An array or a slice is walked by a counted loop over its length, and so is a list, which lends its elements as a slice: none of them makes an iterator object, and the loop is the one a while over the indexes would be. While the loop runs the list may not be changed, since the borrows it hands out would not survive a change. For the same reason an await in the body is refused over an array or a list, whose borrow would have to last across it; over a number range it is fine (An await in a loop).

Changing items in place: mutItems

A plain each only reads. To change the items of a list, an array or a slice where they are, walk mutItems(), which lends each item as a &mut:

each x in list.mutItems() {
  *x = *x * 2;       // x is a &mut of the item
}

It is the same counted loop as a plain each over a slice. The list stays borrowed mutably while the loop runs, so nothing else may read or change it until the loop is over. A list, an array or a slice that is only read has no mutItems to take (an imm list, or a &Array[T] parameter).

A borrow written as the source, each x in &mut list, is refused, in parallel each and in <- each too, with the message to write list.mutItems(): each reads what it walks, and the change in place is a method that lends the items. each x in &list is allowed and reads, as each x in list does.

Taking items out: drain

list.drain() gives the values up one at a time, moving each out of the list into the loop's variable, which then holds the value itself (not a borrow of it), so it works for items such as a String that cannot be copied:

each name in names.drain() {   // name is a String, moved out of names
  joined.append(name.view());
}
// names is now empty (its block is kept for reuse)

The list is left empty as soon as drain is called, and may not be used while the loop runs. Each pass's value is finalized as the pass ends. A loop left early, by break or return, finalizes the values it did not reach.

Positions: indexed

indexed() of a list, an array or a slice gives each position with a borrow of its item, a pair that two variables unpack. Walked directly by each, it is a counted loop, as a plain each is:

each i, name in names.indexed() {   // i is a usize, name a borrow of the item
  print(i, name);
}

A bare indexed() always borrows its items for reading, on a &mut slice as on any other. To change them, call it on mutItems(), a cursor of its own whose indexed() lends each item as a &mut:

each i, p in buf.mutItems().indexed() {
  *p = f(i);                        // p is a &mut of the item
}

Runs: chunks and mutChunks

chunks(n) of a list, an array or a slice hands out its items in runs of n, each run a slice; mutChunks(n) hands each out as a &mut slice, to change in place. The last run is what is left, so it is shorter when n does not divide the count; n larger than the count is one run of everything; an empty source has no run. n of 0 is a panic, at the line of the call. indexed() numbers the runs from 0:

each run in list.chunks(4) {              // run is a &Array[T] of 4 items (the last may be fewer)
  ...
}
each y, row in pixels.mutChunks(width).indexed() {
  each x, p in row.mutItems().indexed() { *p = shade(x, y); }
}

The cursor chunks gives has len (how many runs are left), at(k) (run number k of those left) and split(at) (the runs before run at and those from it on, each a cursor over the same items), so it is a ParallelIterable that cuts only between runs. A parallel each walks it.

For a buffer of pixels, three bytes each, mutArrays[3]() first sees it as a slice of Array[u8, 3] (Seen as Rows), so the runs are rows of pixels and a pixel's channels are indexed: each y, line in pixels.mutArrays[3]().mutChunks(width).indexed() { line[x][0] = ...; }

Two together: zip

zip(&xs, &ys) walks two lists (or deques, sets, dictionaries, or anything else with an iter method) side by side, giving a pair of what each gives, and ends when the shorter does:

each x, y in zip(&xs, &ys) {
  ...
}

An array and a slice have an iter() too (each x in a.iter() is the loop each x in a is), and zip takes them, with the & a list takes: zip(&arr, &xs), or two slice parameters, zip(s, t).

A cursor is zipped with its own method, which takes the other cursor by value (the & of the function would borrow a value that ends with the statement), so a chain goes on from it. Every cursor that declares is Iterator[T] has it (see Adapters), the cursor of a list or an array, a deque, a dictionary, a generator and a cursor of your own, as well as what chunks(n), mutChunks(n) and mutItems() give: xs.iter().zip(ys.iter()), a.mutChunks(n).zip(b.mutChunks(3usize * n)). It gives the same pairs as the function (a tuple, which each x, y unpacks), ends with the shorter, and the pairs can be mapped, filtered and counted like any items: xs.iter().zip(ys.iter()).map(p => *p.0 * *p.1).sum(). The argument is a cursor, not a collection: xs.iter().zip(ys) is refused. Its indexed() numbers the pairs from 0, three variables, the position and one item from each source. each walks it through next.

each y, ra, rb in a.mutChunks(n).zip(b.mutChunks(3usize * n)).indexed() {
  ...                          // ra is a &mut slice of n items of a, rb of 3n items of b
}
each x, y, z in a.mutChunks(n).zip(b.mutChunks(m)).zip(c.mutChunks(k)) {
  ...                          // a third cursor: a flat triple of the three
}

Cursor Iterators

A cursor is anything with a next method that answers an optional value, Some with the next item or None when there are no more. A type needs no declaration to be one, only the method (it is met by shape, as Iterator in the core library names, which is what generic code asks for):

struct Countdown {
  n i32;

  pub fn next(self &mut) Option[i32] {
    if n <= 0 { return None[i32]; }
    imm v = n;
    n = n - 1;
    Some[i32](v);
  }
}

mut countdown = new Countdown(3);
mut digits = 0;
each n in countdown {     // iterates: 3 2 1
  digits = digits * 10 + n;
}

The cursor is used as it is: a cursor in a variable is advanced there, so a loop left with break can be followed by another that carries on from where it stopped. A cursor that lends (a deque's items(), say) gives borrows of its items, as an array does; one that gives values gives the values themselves. An item that moves (a String the cursor hands out) is taken out of the optional value by the one variable, and is the variable's from then on; several variables, which would take the elements of a moving pair out one by one, are refused.

Something that gives a cursor

A value with no next but an iter method, which gives a cursor, is walked through the cursor it gives, as if the loop had called iter itself:

each x in collection {  // equivalent to: each x in collection.iter()
}

The collections give cursors in this way: a deque's, a set's and the dictionaries'. Calling iter only reads the collection: it is borrowed and not consumed, and may not be changed while the loop runs. Other views of a collection are ordinary methods that answer a cursor, walked the same way: each k in dict.keys(), dict.values(), deque.items(), text.chars() (Collection Types).

Two variables

Two or more variables unpack an item that is a tuple. A dictionary's cursor gives its pairs, a borrow of the key and a borrow of the value, so

mut both = 0;
each key, value in ages {   // a Dict[i64, i64]
  both += key * value;
}

and one variable would take the pair whole (pair.0 and pair.1). A number of variables that does not match the tuple, and any number but one for an array, a slice or a list, are refused.

Closure Iterator

Not built yet: each over a closure. Closures are built, but a source for each today is a value with a next or an iter method. The closure spelling below is a sketch. Look to closures for iterator versatility. Using closure iterators, one can scan through elements in a complex collection, retrieve values from a streaming resource, algorithmically calculate a sequence of values, etc. Because closures are stateful, they can generate a new value on every call.

In order for a closure to be suitable as an iterator, it must be able to signal when it is done producing values. It typically does this by returning an optional value, with the value of None signalling when it is done, just as a cursor's next does.

In the following example, imagine a closure that starts off holding the value 12, and halves (and returns) its value on each call. When the value gets to 0, it returns None instead:

mut sum = 0;
each x in |{cnt = 12}| if cnt > 0 {Some(cnt /= 2)} else {None} {
  sum += x;
}

The value of sum at the end will be 10, as each successive call to the closure returns 6, 3, and 1. After 1, it returns None, which stops iteration.

Because it is stateful, a closure is typically single use. It is created before it is needed, used to produce values lazily, and then discarded afterward. This is because, unless its state can be independently reset, it will only ever afterward say it is out of values.

Iterator adapters

Every cursor that declares itself an Iterator has the steps that work on a sequence as a whole, as methods the trait shares: the cursors of the collections (xs.iter(), chunks, mutItems, indexed, a dictionary's, a deque's), a zip, text.chars(), a generator, and a struct of your own that says is Iterator[T], T being what its next gives. A step gives a cursor again; none does any work until a terminal method walks the chain once, from where the cursor is, and leaves it advanced:

imm k = 3;
imm total = xs.iter().map(x => *x * k).filter(y => *y > 9).sum();
each v in xs.iter().map(x => *x * k) {      // a step is a cursor too: each walks it
}

struct Countdown is Iterator[i64] {         // declared: it has map, filter, sum and the rest
  n i64;
  pub fn next(self &mut) Option[i64] { ... }
}
map(f)each item through f; the closure is typed from the item and its result is the new item's type
filter(f)the items f is true of; f is given a borrow of the item
take(n), skip(n)at most the first n items; all but the first n (any integer, a plain literal included; more than there are is none)
zip(other)pairs of an item from this cursor and one from other (a cursor), ending with the shorter (Two together)
fold(init, f)f(result so far, item) over the items, starting from init
any(f), all(f)whether f is true of some / every item; stops at the first that settles it; false / true for no items
count()how many items
find(f)the first item f (given a borrow) is true of, as an Option
sum(), min(), max()for number items: the total (0 for none); the smallest and largest as an Option, None for no items (the first of equals)

An item is whatever the cursor gives. A cursor that lends (xs.iter()) gives borrows, so a closure reads through them: map(x => *x * 2). A filter's closure is given a borrow of the item, a borrow of a borrow for such a cursor, which an operator reads through (filter(y => *y > 3) for either kind). sum, min and max are methods only where the items are numbers (integers, f32, f64), so a cursor that lends is mapped to values first, map(x => *x).max(), and a struct has none of them. find hands the item back, and a borrow cannot be handed back through the chain's steps (each step's next is a method whose signature names no lifetime, so its result is held to lend from the step), so it too is called on values: map(x => *x).find(y => *y == 5).

The closures are generic arguments ([F fn(x T) U]), each its own type, so a chain is compiled into one loop with every closure's body inline and no call through a pointer for any item. A closure that changes a variable (x => { n += 1; *x; }) is run once for each item the chain asks for and no more. Over a cursor that gives numbers (not a borrow), a map and a sum is vectorized as the hand-written loop is. Over a cursor that lends the loop is not vectorized, since each step answers an Option of a borrow, which is a pointer tested for null: the same loop a hand-written while over next() is.

A type with a next that does not declare is Iterator[T] is still accepted wherever an Iterator is asked for as a bound (fn f[T, I Iterator[T]](it &mut I): fitting a trait is by shape), and each walks it. What it does not get is the shared methods, which come with the declaration; asking it for map is an error that says to declare it. Each step is a cursor of its own type (the whole chain's, so a chain is held in a variable of inferred type, or walked at once). The terminal methods take the cursor by &mut, so one called on a chain made in the same expression needs no name for it.

Not built yet: a source that runs its own loop around the body of an each, taking the body as a closure, for a source that cannot hand out its items one by one (a line reader that lends each line from its own buffer, say). each would use it when the source has it, and otherwise use next; break, continue and return in the body would reach the source as signals, and an await in such a body may be refused. The parallel reductions are on their own page. A chain feeding the entries of a collection being built (<- each) is built.

parallel each

Writing parallel in front of an each runs the loop's passes at the same time, on the workers of the actors package. Parallel each describes what it can walk, the rules for its body, filling a buffer, its use in an actor's behaviour, the parallel builder (new List[T] <- parallel each … yield) and the reductions (xs.parallel().sum()).
