Closure References

Note: The closure reference is built, spelled as the signature it calls: &<fn(x i32) i32 borrows anything with a pub () of that signature (a closure, a struct of yours, a plain function through a stub) and only reads it; &<mut fn(x i32) i32 may change what it points at; So[fn(x i32) i32] and Rc[fn(x i32) i32] own one, made as new So[fn(x i32) i32](closure). A closure literal given to a borrowed one is lent for the statement, and a callable held in a field is called by the field's name, b.onClick(3). A closure literal also fills a trait that has exactly one required method and no field, wherever that trait is wanted (a generic's [S Shape], &<Shape, So[Shape]): p => p.length() - 1. is a Shape whose distance it is. The trait's default methods come with it, as they do for any type that implements the trait, and call the literal's body through the required method. A literal takes the self its body needs, and as a struct's must, it may ask for no stronger one than the trait's method declares: a literal that changes state, which needs self &mut, is refused wherever the trait's method says self & (through &<mut Shape too); declare the trait's method self &mut or do not change the state. The examples below, written before this, use the older plus spelling, +So |{window}| and +<So ||, and are to be rewritten.

Earlier, we introduced value-based closures. Value-based closures struggle when we need closures that have a specific calling signature, but whose underlying struct state may vary in size and fields. To satisfy this requirement, a closure may be passed as a virtual reference.

Let's illustrate this with a simple event-handling example:

window.whenClicked(+So |{window}| { ... });

Here we allocate a new click-handling closure using the single-owner region (ensuring it is automatically freed after being triggered and discarded). The closure's state remembers the window, which its logic uses when the window is clicked.

The whenClicked method accepts any closure whose type signature is +<So ||. In other words, it accepts closures having any underlying state, so long as the closure's function signature matches (it accepts no arguments and returns no values).

Closures allocated this way are virtual references. In the same way that closures are implicit structs, closure references take advantage of an implicit trait, one which defines the appropriate method signature for the () method.

When the event fires on a click, the event handler simply calls the closure to perform its defined logic:

handler();
