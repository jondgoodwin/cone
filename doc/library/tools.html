Tools and testing

What builds, checks, observes and demonstrates the language and its packages.

Testing and observing

  • testing [Windows and Linux]: Checks for a package's tests, run by congo test.
  • trace [Windows and Linux]: The facade every package logs and traces through: kinds of event declared once, emitted through macros.
  • logsink [Windows and Linux]: A sink for trace: events written as one text line on standard output or to a file, rotated by size.
  • actortrace [Windows and Linux]: Tracing the actors runtime, a first round: three ways of recording the same events.
  • memstats [Windows and Linux]: Memory instrumentation, off by default: a tagging link shim and core's who-is-asking markers, built with -D MEMSTATS.
  • memtrace [Windows and Linux]: A sink for trace's memory target: what each region asks for, added up by key and sampled every 100 ms, with a report script.

The compiler's own libraries

  • llvmc [Windows and Linux]: LLVM's C API declared by hand, groundwork for a code generator written in Cone.

Samples of language features

  • actortraitlib [Windows and Linux]: Sample: an actor trait that other packages' actors conform to.
  • closurelib [Windows and Linux]: Sample: closures written in bodies other packages use.
  • genwalk [Windows and Linux]: Sample: generators that other packages walk.
  • genuser [Windows and Linux]: Sample: generators that hand on to another package's generators.
  • gpupart [Windows and Linux]: Sample: a program package with a gpu/ folder, a part in two halves.
  • gpusample [Windows and Linux]: Sample: a package of Cone kernels marked for the GPU, compiled for both CPU and GPU.
  • meshedpart [Windows and Linux]: Sample: a part sampled and meshed on the GPU, end to end.
