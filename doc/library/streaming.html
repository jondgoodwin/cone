Networking and streaming

Streams first, then what is streamed: the asynchronous I/O runtime, HTTP, files, archives, compression and messages.

Streams and the I/O runtime

  • streams: The shapes a transform of bytes takes, written once with no I/O inside, plus byte cursors.
  • stages: Stages between actors: a stream of owned chunks handed on under credit.
  • stageio: The ends of a pipeline in the OS: file and socket sources and sinks for stages.
  • iocore: The completion loop of the async I/O runtime: a job handed in, exactly one answer back.
  • aio: I/O an actor awaits: files and connections read and written with await.
  • ioerror: What went wrong with I/O, the same on every system.
  • timewheel: The timers of the async I/O runtime, cheap to arm and to cancel.
  • diag: The async I/O runtime's diagnostics records: where the time went.

HTTP and its clients

  • http: HTTP's messages as data, the same for every version of the protocol.
  • http1: HTTP/1.1's connection core, sans-IO.
  • http2: HTTP/2's connection core (RFC 9113), sans-IO, client or server.
  • http3: HTTP/3 over QUIC's streams (RFC 9114), sans-IO.
  • quic: QUIC version 1 (RFC 9000) over ngtcp2, sans-IO.
  • h3driver: HTTP/3 over real UDP: joins quic and http3 to sockets on an iocore Loop.
  • httpconn: HTTP/1.1 and HTTP/2 connections over the completion loop, client and server.
  • httpclient: HTTP fetched by URL in one call, with pooled connections.
  • actorhttp: HTTP and HTTPS an actor awaits.
  • httpdecode: An HTTP body decoded as it arrives (gzip, deflate, zstd).
  • sse: Server-sent events as bytes, sans-IO: a reader and a writer.
  • tls: TLS 1.2 and 1.3 over OpenSSL 3, client and server, sans-IO.
  • url: URLs as data (RFC 3986): read, resolved against a base, written back.

Files and folders

  • fs: Files and folders, synchronously: read, write, map, list, walk, remove.
  • path: File paths taken apart and put together, as text; asks the file system nothing.

Archives and compression

  • deflate: DEFLATE compression and decompression with zlib and gzip framing, Adler-32 and CRC-32, streaming.
  • zstd: Zstandard decompression and compression (levels 1 to 3), with xxHash64, streaming.
  • zipfile: ZIP archives read, written and extracted safely.
  • tarfile: Tar archives (POSIX ustar) read as bytes arrive and written entry by entry.
  • archivestage: A zip archive read as a stream between actors, each entry handed on as a stream.

Messages

  • netmsg: Application messages over UDP connections (or in-process), an actor per connection with an event handler.
