The Console Log Sink

The logsink package is a trace sink that writes each event as one line of text on standard output. It is the quickest way to see what a program logs: install it, and the kinds and log lines your packages emit appear, filtered by level. It writes to the console, or, through logsink.installFile(path, max), to a file, rotated by size if you ask. There is no colour.

An example

mod app;

import trace use Level, Log;
import logsink;

let log: Log;

fn @initpure init() {
  log = Log.make("app", Level.Info);
}

fn main() i32 {
  logsink.install(Level.Info);
  let id = 42u64;
  log <- $"user {id} logged in";
  0i32
}

prints

2026-11-11T09:30:15.250Z INFO app user 42 logged in id=42

The line

One event is one line: the time, the level, the target, the text, then each field as name=value, separated by single spaces.

  • Time: RFC 3339 in UTC with milliseconds, always 24 bytes. It is the wall clock read when the sink records the event (an event's own time is the facade's monotonic clock, which is no date).
  • Level: the kind's, in capitals: ERROR WARN INFO DEBUG TRACE.
  • Target: the kind's.
  • Text: the event's message; an event with none shows the kind's name. The start and end of an interval add begin or end after it, and span=N after the fields. Control characters are written as \n \r \t \xHH, so an event never spans two lines.
  • Fields: numbers as digits, a bool as true or false, a duration as 830000ns, a time as the facade's tick count. A text value is bare when it is not empty and holds no space, =, quote, backslash or control character; otherwise it is in double quotes with \" and \\ escaped.

What it has

NameWhat it is
install(max)Installs the sink with trace.install. It wants the kinds whose level is no more detailed than max; also sets the facade's default level to max, as Rust's fmt().with_max_level(..).init() does; answers false if a sink is already installed. The facade's own levels (setLevel, CONE_TRACE) still apply.
ConsoleSinkThe sink's type, a trace.Sink.
formatLine(e, at, line)The line layout as a pure function: appends the line for the trace.Event e, as of the wall-clock time at, to the String line.

Lines stay whole

A sink's record runs on the thread that emitted the event, many at once. This one builds the line in a text of its own and prints it with a single print of one text, which stdio takes away whole, so lines from different threads never mix. In a program that runs actors the line is handed, whole, to the console's owner thread like any other print, so a behaviour that logs pays a hand-over, not a write; trace.flush() and the end of the program drain it with the rest.

The file sink

installFile(path, max) opens the file with fs.append (made if missing, an existing file keeps its bytes, so a second run adds to it) and installs a FileSink that writes the same lines. It answers Result[FileLog, FsError]: the open's error if the file cannot be opened, or EBUSY if a sink was already installed. Each event is one write of its whole line, under a mutex, so lines from any threads or actors never mix and each thread's own stay in order; nothing is buffered, so a crash loses at most the event in flight. trace.flush() asks the disk to take the bytes (fsync). A write that fails after the install (disk full) loses its event, is counted, and later events are tried again; FileLog.failures() says how many have failed.

installRotatingFile(path, max, maxBytes, keep) is the same sink with rotation by size. When a line would take app.log past maxBytes, the file is renamed app.log.1, app.log.1 becomes app.log.2 and so on up to app.log.<keep>, the oldest beyond that is deleted, and a fresh app.log takes the line. A line is never split across files: one longer than maxBytes goes alone into a file. keep 0 keeps no old files and maxBytes 0 never rotates (installFile is that case). The rotation happens under the write's mutex, so threads never see a half-rotated log. If the rename is refused (on Windows, another process holds the file open without share-delete) nothing is lost: the file is opened again and keeps taking lines, and the next line tries the rotation again; FileLog.rotationFailures() counts the refusals and FileLog.rotations() the rotations done.
