The Console Log Sink

The logsink package is a trace sink that writes each event as one line of text on standard output. It is the quickest way to see what a program logs: install it, and the kinds and log lines your packages emit appear, filtered by level. It writes only to the console: there is no file sink, no rotation and no colour.

An example

mod app;

import trace use Level, Log;
import logsink;

let log: Log;

fn @initpure init() {
  log = Log.make("app", Level.Info);
}

fn main() i32 {
  logsink.install(Level.Info);
  let id = 42u64;
  log <- $"user {id} logged in";
  0i32
}

prints

2026-11-11T09:30:15.250Z INFO app user 42 logged in id=42

The line

One event is one line: the time, the level, the target, the text, then each field as name=value, separated by single spaces.

  • Time: RFC 3339 in UTC with milliseconds, always 24 bytes. It is the wall clock read when the sink records the event (an event's own time is the facade's monotonic clock, which is no date).
  • Level: the kind's, in capitals: ERROR WARN INFO DEBUG TRACE.
  • Target: the kind's.
  • Text: the event's message; an event with none shows the kind's name. The start and end of an interval add begin or end after it, and span=N after the fields. Control characters are written as \n \r \t \xHH, so an event never spans two lines.
  • Fields: numbers as digits, a bool as true or false, a duration as 830000ns, a time as the facade's tick count. A text value is bare when it is not empty and holds no space, =, quote, backslash or control character; otherwise it is in double quotes with \" and \\ escaped.

What it has

NameWhat it is
install(max)Installs the sink with trace.install. It wants the kinds whose level is no more detailed than max; answers false if a sink is already installed. The facade's own levels (setLevel, CONE_TRACE) still apply.
ConsoleSinkThe sink's type, a trace.Sink.
installWith(max, clock, write)For tests: the same, with the clock and the function that writes a line given.

Lines stay whole

A sink's record runs on the thread that emitted the event, many at once. This one builds the line in a text of its own and prints it with a single print of one text, which stdio takes away whole, so lines from different threads never mix. In a program that runs actors the line is handed, whole, to the console's owner thread like any other print, so a behaviour that logs pays a hand-over, not a write; trace.flush() and the end of the program drain it with the rest.
