Vectors: many numbers at once

Note: Not built yet: swizzles such as v.xyz, loading and storing a vector straight from a slice, gather and scatter, a vector in a global, and a generic that takes its lane type or count from the vector it is given: a generic over a vector is written with them, twice[f32](v). The numbers have no abs, min, max, floor, ceil, round or fma to give a vector's lanes yet.

A processor can add four numbers in the time it takes to add one, if the four sit side by side in one of its wide registers. A vector, Vector[T, N], is N numbers of type T held that way, the lanes of the vector, and an operator on two vectors is one instruction that works on every lane at once. This program prices four items, each with its own discount:

mod lanes;

import stdio use *;

fn main() {
  let price = Vector[f32, 4]() <- 10.0, 20.0, 30.0, 40.0;
  let off = Vector[f32, 4]() <- 0.5, 0.25, 0.0, 0.1;
  let paid = price - price * off;        // all four at once
  print <- "paid: ", paid[0], " ", paid[1], " ", paid[2], " ", paid[3], "\n";
  print <- "total: ", paid.sum(), "\n";

  let limit = Vector[f32, 4]() <- fill 20.0;
  let cheap = paid < limit;              // true in the lanes under 20
  print <- "any cheap: ", cheap.any(), ", all cheap: ", cheap.all(), "\n";
  let shown = cheap.select(paid, price); // the discounted price where cheap, else the full one
  print <- "shown: ", shown[0], " ", shown[1], " ", shown[2], " ", shown[3], "\n";
}

It prints:

paid: 5 15 30 36
total: 86
any cheap: true, all cheap: false
shown: 5 15 30 40

A vector is a value, copied as a number is. It sits in a register where the processor has one wide enough, is passed to and returned from functions that way, and is aligned as its whole is: sixteen bytes for four f32, so a struct holding one is padded to fit it.

The type: Vector[T, N]

The lanes are all one number type T: any integer type or f32 or f64. N is a whole number from 1 through 64, written as a literal, and need not be a power of two: Vector[f32, 3] is a three-lane vector that takes sixteen bytes, one lane being padding. Vector[f32, 4] is what C calls an __m128 and a shader calls a vec4; the size and alignment of any vector are the target's. A vector is Sendable and Shareable like the numbers it holds.

It is not an Array[T, N], though the two convert (below). An array keeps C's exact layout, a lane count of three taking three numbers, and is aligned as its element is; a vector is aligned and passed as a whole. And a + b on arrays would surprise, where on vectors it is the point.

A program compiled with no --cpu option targets the portable baseline, which on x86-64 is SSE2: 128 bits, four f32 a register. A wider vector, Vector[f32, 8], is still correct there, as two operations; --cpu native compiles for the machine's own CPU and its wider registers, and a program built with it runs on that CPU and those like it.

Making a vector

A vector is constructed with its contents, as an array is: its type, empty parentheses, <- and the values, which fill it exactly. The forms are the array's: values listed, n of x, and fill x for as many lanes as are left (Contents). A value that is repeated is evaluated once for each lane.

let v = Vector[i32, 4]() <- 1, 2, 3, 4;
let zeros = Vector[f32, 8]() <- fill 0.0;
let mixed = Vector[u8, 4]() <- 7, 3 of 0;     // 7 0 0 0

A vector and an array of the same lane type and size convert to each other, and the conversion costs nothing. They are the from of the numbers (Converting between number types):

let a = [1.0f, 2.0f, 3.0f, 4.0f];
let v = Vector[f32, 4].from(a);          // an array in, a vector out
let back = Array[f32, 4].from(v);        // and back again

A vector also converts to a vector of the same number of lanes and another lane type, each lane as the number type's own from converts it. A float that does not fit the integer it becomes gives the integer's nearest end, and a NaN gives 0, never garbage; an integer into a narrower one keeps its low bits, and a number into bool asks whether it is not zero:

let f = Vector[f32, 4]() <- 1.9, -1.9, 300.0, 0.0;
let i = Vector[u8, 4].from(f);           // 1 0 255 0

Lanes of different types are never mixed by an operator: Vector[f32, 4] + Vector[i32, 4] is refused, and the message names the conversion that makes them one.

One lane: v[i]

v[i] is lane i, counting from 0, an unsigned integer index. It is a place: it can be read, assigned and changed in place, and an index past the last lane is a panic at the line, as an array's is.

var v = Vector[i32, 4]() <- fill 0;
v[2] = 9;
v[1] += 3;                  // 0 3 9 0

A lane is not borrowed (&v[i] is refused): it lives in the register. Read it or write it.

Operators

Every arithmetic operator works on the lanes pair by pair: +, -, * and /, unary -, and % on integers. On integer lanes so do the bitwise operators &, |, ^, ~, << and >>. Each lane does what the number type does: an integer lane wraps as an integer does, and a shift by the width or more gives 0 (the sign for a signed >>). The assignment forms, += and the rest, work too.

A number beside a vector is used in every lane, on whichever side it is. It must be the lane type, or a literal that takes it:

let v = Vector[f32, 4]() <- 1.0, 2.0, 3.0, 4.0;
let w = 2.0 * v + 1.0;      // 3 5 7 9

Dividing integer lanes checks first: if any lane of the divisor is zero, or any lane divides the type's smallest number by -1 (whose quotient does not fit), the program panics, at the line, before dividing. It is one comparison of the lanes and one test, not a test for each. % is checked the same way.

Comparisons and masks

==, !=, <, <=, > and >= compare the lanes pair by pair and give a mask, a Vector[bool, N] with true in each lane where the comparison holds. A mask is a vector of bool, not of numbers: it has &, |, ^, ~, == and != and nothing arithmetic, so adding two masks is refused rather than quietly counting. Three methods put one to use:

  • m.any() and m.all(): is it true in some lane, in every lane.
  • m.select(a, b): a vector of a's lane where the mask is true and b's where it is not. a and b are vectors of the mask's number of lanes and one type, or one is a number used in every lane.

A mask's lanes are not indexed; test them together, or choose with select. To count them or use them as numbers, convert: Vector[u8, 4].from(m) is 1 where true and 0 where not.

Reducing a vector to one number

sum(), product(), min() and max() combine all the lanes into one number of the lane type. For floats, sum() adds the lanes in order, lane 0 plus lane 1 plus lane 2, as a loop over the lanes would, so the same lanes give the same answer on every machine; min() and max() of floats take a number over a NaN. A dot product keeps a vector of partial sums, so the running sum is taken a vector at a time, and reduces it once at the end:

fn dot(a: &Array[f32], b: &Array[f32]) f32 {
  let ra = a.asArrays[8]();            // the slice seen as rows of eight
  let rb = b.asArrays[8]();
  var acc = Vector[f32, 8]() <- fill 0.0;
  each i in 0usize ..< ra.len() {
    acc += Vector[f32, 8].from(ra[i]) * Vector[f32, 8].from(rb[i]);
  }
  acc.sum()
}

This adds the products in eight separate running sums, not one, so its last digits differ from a loop adding them one at a time; nothing in the language reorders a float sum for you, which is also why the compiler cannot turn the plain loop into this one.

Math on the lanes

A vector of floats has the floats' sqrt, sin and cos, applied to every lane (Methods on numbers).
