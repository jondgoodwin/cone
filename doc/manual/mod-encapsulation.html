Encapsulation

Publish the interface, hide the rest

Encapsulation treats a component as a black box. It publishes an interface, the names other components may use, and it hides everything else: the logic that does the work, and the state and structures it does it with. Done well, it reduces coupling, because there is less for anyone outside to depend on; it lets a reader hold a part in mind without holding all of it; and it keeps most changes local, since what nobody outside could reach, nobody outside can be broken by.

In Cone the boundary is the module. A name declared pub is the module's interface, and every other name is private to the module, whatever kind of name it is: a function, a global, a type, or a type's field or method. The same idea comes back at the other layers:

  • A block's local variables are private to the block (Function Blocks).
  • A type's members that are not pub are private to the module that declares the type (below).
  • An opaque type, declared struct @opaque SocketHandle;, hides even its size and layout: its values are reached only through references or pointers, and its fields are never read.
  • An actor's state is private to it: a field of an actor is never pub, and nothing outside the actor reaches one (Private state).
  • A type that enriches another is inside its base's encapsulation, and sees what the base's own methods see.

A module's names

Module names are:

  • unique. no two items in a module may have the same name. Several functions may nonetheless share one overload name, which is itself a single name in the module that maps to those functions. A module may not bring one name in twice, even for the same item: listing a name twice, writing the same use twice, importing a module twice, or importing a module and also listing it through another module that re-exports it, is an error. Core is imported into every module automatically, so import core in any module but a C-named one is a second import of it, and the error says so. What a module never wrote is different. When a name arrives by a wildcard use *, by extends, or by the automatic import of core, and it is the same item the name already has, it is not two items: when two wildcard imports each re-export the same function, a module that extends this one hands this one's own names back, or import libc use * brings the malloc core already re-exports from it, the name is bound once, and it is public if either route made it public.
  • order-independent. One can reference functions, variables, or types whose names are not defined until later in the module. The only exception to this are permissions and regions whose definition must precede their use.
  • private unless pub. A name declared pub may be referenced outside the module. Any other name may not: it is private to the module, whatever it is spelled. The interface of a module is what it says it is, and nothing more. A type's members that are not pub are private to its module in the same way (A type's names).

What pub means for the other things a module holds is on the pages that describe them: a submodule is private to its parent unless it is written pub mod, and the names an import or a use folds in are private to the module that folds them unless it writes pub.

A type's names

A type's names are:

  • unique for every field, function and method. Every method and function has its own name, unique within the type. Several methods or functions may additionally share one overload name, which they declare with overload.
  • order-independent. A name may be referenced before its declaration, and the order in which the methods or functions sharing an overload name are declared never affects which one a call selects.
  • private to the module unless pub. A field, method or function declared pub may be used anywhere the type's values reach. Any other member is private to the module that declares the type: every function, method and type of that module may use it, through any value of the type, in any file of the module's folder, and nothing outside the module may. A sister, a submodule and the parent are other modules, as is a file that opens with its own mod line. A type that extends another, a struct enriching its base or an enum extending its base, is the one exception: it is inside its base's boundary, so its code reaches the base's private members wherever it is declared. Fields and methods are accessed on a value using the dot (.) operator. A static function is reached with the same operator, on the type's name.
  • a pub field of a pub type names only types the outside can name. Such a field is reached from outside the module, so a type private to the module may not be its type, alone or behind a reference, a pointer, an array or a type argument. Either the field is made private, which the module still reaches, or the type is made pub.

A type's members and a module's names share one privacy boundary, the module. The module is the unit of trust: the code that may see a type's private members is decided by where it is written, not by a list the type declares, so there is no friend declaration. A type whose state must be kept even from its neighbours is declared in a module of its own.
