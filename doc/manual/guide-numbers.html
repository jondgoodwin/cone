Numbers

The number types, their literals, the operators that compute with them, and how a number changes from one type to another.

Literals

A literal is a specific, unchangeable value. Each of these numbers is a literal:

123
3.14159
1e6          // 1000000.0
-1_000_000   // underscores are ignored
0x1000       // Hexadecimal

Beyond numbers, other forms of literals will be introduced later, including:

  • string and character literals (e.g., "Hello" and 'a')
  • boolean true and false
  • struct, array, and other compound values

Integers and floats

The built-in number types specify their bit-size as part of the type's name. Here they are:

  • Signed integer types: i8, i16, i32 and i64
  • Unsigned integer types: u8, u16, u32 and u64
  • Floating point types: f32 and f64

Later, a number of other types will be introduced.

Typed Number Literals

To explicitly specify the type for a numeric literal, append the type name right after the number:

65u8       // 8-bit unsigned integer
1f64       // 64-bit floating point number

If the type is omitted, the number is understood to be 32-bits. When the number explicitly includes a decimal point or exponent, it is treated as a floating point number (f32). Otherwise, it is considered to be a signed integer (i32).

3.14159    // f32 (because of the decimal point)
1e6        // f32 (because of the exponent)
1_000_000  // i32 (no decimal point or exponent)

Type name shortcuts are also supported:

1000u      // u32
1f         // f32
1d         // f64

An integer's bits

Every integer type (u8 to u64, i8 to i64, usize and isize) has methods that count and move its bits. Each count is a u32, and each is defined for 0, as the width:

x.countOnes()
How many of its bits are 1.
x.leadingZeros()
How many bits are 0 above its highest 1: the width, for 0.
x.trailingZeros()
How many bits are 0 below its lowest 1: the width, for 0.
0x2Cu8.countOnes()        // 3
1u64.leadingZeros()       // 63
0u32.trailingZeros()      // 32
(-1i16).countOnes()       // 16: a signed integer's bits, the sign's among them

The rest take an amount n, a u32, and use it modulo the width, so every amount has an answer and 0, the width and twice the width give the same one:

x.rotateLeft(n), x.rotateRight(n)
The bits moved by n, those shifted out of one end coming in at the other.
x.shlMasked(n), x.shrMasked(n)
A shift by n modulo the width: the shift most processors do in one instruction. shrMasked fills with the sign bit on a signed integer and with zeros on an unsigned one. The operators << and >> differ only past the width, where they shift every bit out (Shift operators).
0x81u8.rotateLeft(1)      // 0x03
1u32.shlMasked(33)        // 2, a shift by 1
1u32 << 33u32            // 0
(-16i8).shrMasked(10)     // -4, a shift by 2

The same operations are core's intrinsics, mem.countOnes(x) and the rest (Intrinsics), whose type parameter is any of these integer types.

The primitive 'int' and 'float' number types

Note: The primitive int- and float- types are not implemented, and the standard number types (i32, f64 and the rest) are built into the compiler rather than defined in a library. A custom number type written as below, with a standard number type as its field in place of int-32, does work: a struct wrapping the number, methods on it, and its conversion from a number, Nbr32.from(somenbr), declared as below. The standard number types' from is built into the compiler with them, and so are an integer's bit methods, which are implemented.

int-32 specifies a 32-bit integer. Any integer value from 1 to 128 may be specified after the dash, to establish the number of bits.

Similarly, float-32 is a 32-bit floating point number. Floats only support 32 and 64-bit values.

Unlike i32, int-32 does not define any methods for manipulating its values (e.g., adding and subtracting). It is also agnostic on the semantic interpretation of its values ... it does not even signify whether the integer value should be interpreted as signed or unsigned. Its lack of built-in methods and interpretation is what makes it an ideal foundation for defining new types with very different interpretations and methods.

Custom Number Types

Rarely needed, and largely hypothetical for now (see the note above): defining a number type of your own.

There are several reasons why we might want to define distinctly different number types than those provided by the standard library:

  • One might want to use different types to distinguish between units of measure, thereby potentially avoiding problems like the loss of the $125 million Mars probe.
  • Different number types could make different promises for undefined behavior (e.g., protecting against undesired overflows), or could guarantee the number values are bounded by some range.
  • Integers that support intrinsic atomic operations can be separately typed, as the core package's Atomic[T] is.

Creating a new numeric integer type is nearly as simple as wrapping an primitive integer type as a field in a struct. For example:

struct Nbr32 {
    pub nbr int-32;
}

Methods may be added to this struct to define the operations that may be performed on values of this type. These methods can make use of fast internal integer primitive functions (TBD).

Although numbers of one type are never implicitly converted into the equivalent number of another type, a conversion may always be asked for explicitly. A conversion is a method of the type converted to, named from and called on the type, which takes the value to convert:

imm converted = Nbr32.from(somenbr);

Every standard number type has one, which takes a value of any number type (Explicit Conversion). A custom number type declares its own, an ordinary function of the type:

struct Nbr32 {
    pub nbr int-32;

    pub fn from(n i32) Nbr32 {
        new Nbr32(n);
    }
}

from is the type's default conversion from another type. A conversion that differs from it, such as one that saturates at the type's limits or one that checks that the value fits, is an ordinary method with a name of its own.

Operators and precedence

Note: All of this capability is implemented except the special my name and max and abs on numbers, which are not built.

Now that we have literals and variables, we can construct more complex expressions that use operators, methods and functions calls to calculate new values. Although the expression examples on this page work with integer and floating point values, similar expressions can be formulated that manipulate values of other types.

Expressions are gathered into blocks. A block is the basic unit for structured control flow. It holds a ordered collection of statements that are executed in order, starting with the first statement. It may also accumulate its own temporary, local state. Blocks that evaluate to some value may also be used in expressions.

Arithmetic Operators

Integer and floating point numbers may be computed using arithmetic operators:

'+'
Add
'-'
Subtract (or negate when used as a prefix operator)
'*'
Multiply
'/'
Divide
'%'
Modulo (remainder)

Thus:

-12 + 14    // 2
6 / 5       // 1
-4 % 3      // -1 (where -4/3 --> -1, truncating towards zero)
2*2 + 2*3   // 10 (standard algebraic operator precedence)
2 * (4 + 1) // 10 (parentheses override operator precedence)

Bitwise expressions

The bitwise operators operate on true/false values:

'|'
Or
'&'
And
'^'
Xor
'~'
Not

For example:

true | (false & true) // true
true ^ ~true          // true

These bitwise operators may also be used on unsigned integers, as they are viewed as a collection of true/false bits.

0xE0u | 0xB8u  // 0xF8u

Shift operators

The shifting of an integer's bits is accomplished using the << and >> operators:

0x0Cu << 1    // 0x18, after shifting bits left once

The amount to shift by is a value of the same integer type. << fills the bits it vacates with zeros, and the bits shifted past the top are gone. >> on an unsigned integer fills with zeros; on a signed integer it fills with copies of the sign bit, so a negative value stays negative.

Every amount gives an answer, the same in every build. An amount of the integer's width or more shifts every bit out: << gives 0, as does >> on an unsigned integer, and >> on a signed integer gives the sign in every bit, 0 or -1. The amount is read as an unsigned number of its own width, so a negative amount of a signed type is past the width too:

imm n = 64u64;
255u64 >> n         // 0
(1u64 << n) - 1u64  // all ones: 1 << 64 is 0
-8i32 >> 40i32      // -1, at run time

In a constant expression, such as a const's value, a shift by the width or more, or by a negative amount, is an error.

An amount taken modulo the width is asked for by name: the integer methods shlMasked and shrMasked, the processor's one-instruction shift, and rotateLeft and rotateRight (An integer's bits).

Numeric conversions

To convert a number from one type to another, call the intended type's method from with the number:

imm six = i32.from(6u8);    // Converts 8-bit unsigned integer to 32-bit signed integer
imm sixf = f64.from(six);   // Converts 32-bit signed integer to 64-bit floating point number

If the receiving number type is a smaller size, numeric information may be lost. Explicit Conversion gives what each conversion does.

Explicit Conversion

Type conversion involves transforming a value of one type to the closest possible value in another type. For example, converting the integer 1 to the floating point number 1.0, or serializing it to text: "1". Unlike coercion, conversion may not map perfectly: A valid mapping may not exist or some precision may be lost.

A conversion is not a construction but a method of the new type, from, called on the type with the value to convert. It is the type's default conversion from another type; any other way of converting, such as one that saturates at the type's limits or one that checks that the value fits, is an ordinary method with a name of its own.

imm float = f32.from(1);
imm count = u32.from(list.len());
imm name = String.from("node");    // collections' String, from a slice of bytes

Every number type has from, which takes a value of any number type. It may be called on the type named directly, through an alias of it, or on a generic's type parameter: T.from(x) converts to whichever type T is. The into operator is retired: from is the conversion. Between numbers it does what the machine does:

  • To a narrower integer, the low bits are kept: u8.from(300) is 44.
  • To a wider integer, a signed value converting to a signed type is sign-extended; every other value is zero-extended from its own width, so u64.from(-1i8) is 255. Between a signed and an unsigned type of one width, the bits are kept: i8.from(200u8) is -56.
  • A float converts to an integer by truncating toward zero: i32.from(-2.75) is -2. A float whose truncated value the integer type cannot hold, a negative one to an unsigned type among them, has no defined result.
  • An integer converts to the nearest float, and a float to the nearest float of the other width.
  • An integer literal with no suffix is an i32 and converts as one: u64.from(-1) is 4294967295. Converting a literal gives a literal, so it may be a global's value.

Converting a number, reference or pointer to bool, written bool.from(n), gives the answer its isTrue method gives a condition (see Implicit Coercion to bool): bool.from(2) is true, as are bool.from(0.5) and NaN; only 0, -0 and a null pointer are false. A bool converts to a number as 0 or 1.

A number type takes no square brackets: u64[count] is an error naming u64.from(count).

In some cases, it may be more convenient to request conversion by using some method in the old type:

imm text = 1.text;

Assignment forms: +=, ++

An 'lval'-based expression is one where the expression to the "left" represents a memory "container" which holds a value. Lval-based expressions will change the stored value. The assignment expression introduced on Variables, types and expressions is lval-based, as examples specified a variable to the left of the =. Parallel assignment, a, b = b, a, is with tuples.

Increment/decrement Operators

When used to the left of an lval, ++ will increment the number and -- will decrement it.

mut cnt = 10;
++cnt;          // 11
--cnt;          // 10

When used to the right of an lval, it will still increment and decrement, but the expression will return the original value.

mut cnt = 10;
imm x = cnt++;  // x is 10, cnt is 11

Arithmetic Assignment

The arithmetic assignment operators (e.g., '+=', '-=', '*=', '/=') offer a convenient way to update an existing stored value:

counter = 3;
counter += 1;  // 4. Equivalent to: counter = counter + 1

Logical assignment operators

These work similarly to the arithmetic assignment operators:

mut flags = 0xC0u;
flags |= 0x01u;   // 0xC1u
flags >>= 1;      // 0x60u
