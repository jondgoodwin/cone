Memory in Depth

This part is for a programmer who has read The Guide and wants the full rules behind what happens to a value: when it is copied and when it moves, what a permission allows, how long a borrow may live, and where a value's memory comes from and when it goes back. The Guide's Values, variables and expressions has the short version of moving. Each page here runs from what most programs meet to what few need, ending with writing a region of your own.

In addition to borrowed-references, Cone also supports region-managed references. Region-managed references are also pointers to values and are constrained by permissions, both static and lock.

The key difference is that every region-managed reference belongs to a memory region in the heap which manages the ways its values are allocated and freed. This is in contrast to a borrowed reference, which has no idea which memory region holds the value it points to.

In this part

  • Moves in Depth: which types move and which copy, what a move leaves behind, conditional moves and drop flags, moving out of fields, swap.
  • Permissions in Depth: the static permissions (uni, mut, imm, ro, opaq and the rest), transitions between them, recovery, and what a reference held in a field allows.
  • Borrowed References in Depth: making a borrow, using one, and the lifetime and shape-change rules that keep every borrow sound.
  • Lifetimes: lifetime annotations on signatures, structs and bounds, for when the compiler needs to be told.
  • Owning References and Regions: new, the owning reference types, and the regions that manage memory: So, Rc, Arc, the collectors, arenas and pools.
  • Weak References: references that do not keep their value alive, for breaking cycles.
  • Collections in a Region or Arena: where a collection's block comes from, and collections of garbage-collected references.
  • Roll Your Own: A Region of Your Own: writing a region as a struct, the methods the compiler calls, and tracing.
