Collections and the send operator

An array's size is fixed when the program is compiled. Most programs gather values whose number is known only when they run: the words of a text, the users of a service, the orders of the day. A collection holds as many as it is given. This page counts the words of a sentence with the four you will reach for most often: List, Dict, Set and String.

// Word frequencies: which words a text uses, and how often
mod wordfreq;

import stdio use *;
import collections use *;

struct Tally {
  pub word String;
  pub count i64;
}

fn main() {
  // A String is a collection of bytes, changed here in place
  mut text = String.from("The cat sat on the mat and the dog sat on the log");
  text.lowerAscii();

  // A List of Strings, one for each word
  imm words = text.split(' ');
  print <- words.len(), " words\n";

  // A Dict from each word to how many times it appears
  mut counts = new Dict[String, i64];
  each w in words {
    imm before = match counts.getCopy(w) {     // an Option: Some(count), or None
      case imm n Some {n;}
      case None {0;}
    };
    counts <- w.copy(): before + 1;           // a key and its value; the new count replaces the old
  }
  print <- counts.len(), " different words\n";

  // Build a List from the Dict, then sort it: most frequent first, ties alphabetical
  mut ranked = new List[Tally] <- each e in counts.entries() yield new Tally(e.key.copy(), e.value);
  ranked.sortBy((a, b) =>
    if a.count != b.count {i32.from(b.count - a.count);}
    else {bytesCompare(a.word.view(), b.word.view());});

  // Gather the first three into one line of text
  mut top = String.from("top three:");
  each t in ranked.iter().take(3) {
    top <- " ", t.word.view(), "=", t.count;
  }
  print <- top.view(), "\n";

  // Adapters work on a sequence as a whole
  imm total = ranked.iter().map(t => t.count).sum();
  imm repeated = ranked.iter().filter(t => t.count > 1).count();
  print <- total, " counted, ", repeated, " words used more than once\n";

  // A Set of the words used only once
  imm once = new Set[String] <- each t in ranked if t.count == 1 yield t.word.copy();
  print <- once.len(), " used once";
  if once.contains("cat") {print <- ", the cat among them";}
  print <- "\n";

  // pop takes the last value out; peek looks at the new last one
  match ranked.pop() {
    case imm t Some {print <- "last: ", t.word.view();}
    case None {print <- "no words";}
  }
  match ranked.peek() {
    case imm t Some {print <- ", then ", t.word.view(), "\n";}
    case None {print <- "\n";}
  }
}

It prints:

13 words
8 different words
top three: the=4 on=2 sat=2
13 counted, 3 words used more than once
5 used once, the cat among them
last: mat, then log

What to notice

  • import collections use *; brings in List, Dict, Set and String.
  • <- gives values to a collection: a word and its count to the Dict, text and numbers to a String, and, after new List[Tally], an each … yield that builds the whole list in one line.
  • each walks a collection as it walks a range. iter() hands the values out one at a time, and steps such as take, map, filter, sum and count work on them as a whole.
  • getCopy, pop and peek may have nothing to give, so each answers an Option, and a match asks which.
  • sortBy is given a closure that says which of two tallies comes first.

Why lists grow

A List[T] is an array that grows. It keeps its values side by side in one block of memory, and when the block is full it moves them to one twice the size, so there is always room for one more. It can be built with its first values, and given more at any time:

mut primes = new List[i32] <- 2, 3, 5;    // built with its first values
primes <- 7;                               // <- pushes onto the end
primes.push(11);                           // the same, by name
primes <- 2 of 0;                          // two more values, both 0

mut sum = 0;
each p in primes {
  sum += p;                                // 28, over all seven
}

primes.len() is 7. primes[1] is the value at position 1, which is 3, since positions count from 0. A position past the end stops the program with a panic that names the index and the length, as an array's does. To ask instead, primes.get(20) answers an Option that says whether there is a value there.

Finding things by key: Dict and Set

A Dict[K, V] pairs each key with a value, and finds the value again by its key. The keys may be integers, a bool, a String, or a struct of your own that says it can be hashed. The program counts with one: counts <- w.copy(): before + 1 puts a word and its count in, and a later count for a word it already holds replaces the earlier one. The key is handed to the dictionary, which keeps it, so the program gives it a copy of the word and keeps its own. A dictionary whose keys are Strings is asked with plain text: counts.contains("the").

imm ages = new Dict[String, i64] <- String.from("Ann"): 31, String.from("Bo"): 12;
mut adults = 0;
each name, age in ages {       // two variables: each key, and its value
  if age >= 18 { adults += 1; }
}

A dictionary is unordered: the order it visits its keys in changes from one run to the next, so a program that prints them in order sorts them first, as the word counter does. An OrderedDict, with the same methods, visits them in the order they were put in.

A Set[T] is a dictionary of keys alone: it says whether it holds something. insert adds an element and answers whether it was new, contains asks, and remove takes one out. The program's once is a set of the words used only once, and once.contains("cat") finds the cat among them.

A String is a collection too

String is text that grows: a list of bytes that is read as text. The program changes one in place (text.lowerAscii()), splits one into a List of Strings (text.split(' ')), and builds one up with <-, which appends text or a number: top <- " ", t.word.view(), "=", t.count. top.view() is its text, as print takes it. Text has the rest of what a String does.

Walking a collection

Loops walked a range with each. Over a collection it is the same loop: each w in words visits the words in order, two variables take each key and value of a dictionary, and a set gives each element. The loop reads the collection where it lies, so the collection cannot be changed while the loop walks it. To take the values out as you go, walk drain(), which hands each one over and leaves the list empty:

mut names = String.from("ann,bo,cy").split(',');
mut joined = String.from("");
each name in names.drain() {     // each String is handed over, not copied
  joined <- name.view(), ";";
}
// joined is "ann;bo;cy;" and names is empty

iter() gives a cursor, which hands out a collection's values one at a time. A cursor has steps that work on the values as a whole. Some give a cursor again: map turns each value into another, filter keeps those a test is true of, take(n) keeps the first n and skip(n) drops them. Others walk the chain once and answer: sum, count, min, max, any, all, find and fold. A chain does no work until one of these walks it, and it is compiled into one loop:

imm total = ranked.iter().map(t => t.count).sum();
imm repeated = ranked.iter().filter(t => t.count > 1).count();

The steps take closures, small functions written where they are used, and so does sortBy, whose closure answers which of two values comes first: a negative number for the first, a positive one for the second, and 0 when either may go first.

The send operator

Everything given to a collection above went through <-, the same operator print has used since the first program. It is the one operator for giving values to anything that takes them. What follows it is a list, each entry given in turn, and an entry may be more than a value:

  • 2 of 0 gives the same value several times;
  • fill 0 gives it until a collection made with room for some number of values is full;
  • word: count gives a key and its value together;
  • each gives every value a loop makes, and with a yield in place of the loop's body it builds one collection from another:
imm squares = new List[i32] <- each i in 1 .. 5 yield i * i;     // 1 4 9 16 25
imm once = new Set[String] <- each t in ranked if t.count == 1 yield t.word.copy();

When there may be nothing: Option

pop takes the last value off a list, but the list may be empty. peek looks at the last value, get at a position that may be past the end, and getCopy for a key the dictionary may not hold. So each answers an Option: an enum, declared by the core library as Result is (Enums), whose value is Some(value) when there is one and None when there is not. A match finds out which: case imm t Some hands over the value, and case None is the empty-handed case. That is all there is to it; its complete rules are with the enums.

Where a collection's memory lives

A collection keeps its values in one block of memory, which it gets, grows and gives back as it needs. That block comes from a region: the heap's, unless the collection was made in another. Nothing in this page had to say so. A collection made with new or empty() takes the heap's, and when the collection dies it finalizes each value it holds and gives its block back. Why there is more than one kind of region is a story for later, and it begins like this:

Unusual among languages, Cone conceptually partitions the heap into regions. Each region has its own strategy for allocating and automatically reclaiming memory that holds values. Every program value on the heap is wholly located within and governed by its owning region.

The reason Cone supports multiple regions is because there is no one perfect strategy for allocating and automatically freeing memory. Each strategy (e.g., tracing GC, ref-counting, single-owner, pools or arenas) carries different trade-offs in terms of throughput, latency/responsiveness, memory use and leakage, data structure flexibility, and programmer convenience.

The rest is in Owning references and regions, and a collection made in a region of your choosing is in Collections in a region or arena.

In detail

The rest of this page is the complete reference for collections, iteration over them and the send operator; skip to the next page if the program above was enough.

Note: A Set has no union or intersection yet, and no trait covers a set's insert and remove. The send operator's list of entries (values, n of x, fill x, pairs and each) is implemented, after a value and after a construction.

A collection type holds some number of values (elements) that are all the same type. The standard library offers a number of versatile collection types, such as List, Deque, Dict, OrderedDict and Set.

All such collection types are built on top of the array primitive types, whose elements are co-located in memory and are individually accessed using an integer index:

  • Array types. An array has a statically known size.
  • Array reference types. An array reference, a slice, is a borrowed view of some runtime-determined number of elements of the same type: all or some of the elements of an array, or of a collection. It owns none of them. An array whose length is chosen at runtime is a collection.

The library collection types are the collections package's List[T], Dict[K, V] (keyed by any type that is Hash), OrderedDict[K, V] (the same, visiting in insertion order), Set[T] and Deque[T], with String beside them (import collections use *;). A list or a dictionary is constructed with new, its first values after <-: new List[i32](100) <- fill 0 (a collection's contents). Each holds its elements in one block it gets from its region (the heap's unless it was made in another; Collections placed in a region) through a raw pointer, not in an array reference.

Lists

A List[T] is a growable array: pushing onto it makes room as it needs, doubling its block as it fills. xs <- v is a push. An element is read with xs[i], which is a borrow of the element, so it is dereferenced to get the value, and &mut xs[i] borrows it to change.

import stdio use *;
import collections use *;

fn main() i32 {
  mut xs = List[i32].empty();
  xs.push(3);
  xs <- 4;                       // <- is push
  xs.push(5);
  print <- xs.len();
  print <- "\n";
  print <- *xs[1usize];          // an element is a borrow, so dereference it
  print <- "\n";
  match xs.pop() {
    case imm v Some {print <- v; print <- "\n";}
    case is None {print <- "empty\n";}
  }
  match xs.get(7usize) {         // get does not panic
    case imm v Some {print <- *v; print <- "\n";}
    case is None {print <- "no seventh\n";}
  }
  mut total = 0;
  each x in xs {                 // walks the slice the list lends
    total += *x;
  }
  print <- total;
  print <- "\n";
  imm zeros = new List[i32](5) <- fill 0;
  print <- zeros.len();
  print <- "\n";
  0i32;
}

This prints 3, 4, 5, no seventh, 7 and 5, one to a line. peek() (an Option of a borrow of the last value) and get(i) (the same for position i, None past the end) do not panic.

A list is String's twin for any element. list.view() lends its elements as a &Array[T], the slice, and the list folds the methods of Array[T] in as its own (list.len is Array[T]'s). list.viewMut() lends them as a &mut Array[T], and a list reached only by a &uni (a &uni parameter, (&uni list).viewUni() for a local) lends them as a &uni Array[T], viewUni, which a parallel each that changes its items may take as its source; a String's bytes likewise.

list.freeze() consumes the list and moves its elements, uncopied, into a fixed-size owner (Freezing a list).

Freezing a list

list.freeze() consumes the list and moves its block, shrunk to the elements it holds, into a So[Array[T]]: the elements are not copied, move types included, and the owner's death finalizes each of them once. A list that holds nothing makes a one-byte block, since the owner of an Array[T] always owns heap bytes (owned arrays).

Dictionaries and sets

Dict

Dict[K, V] is a SwissTable: an open-addressed table with a control byte for each bucket (empty, removed, or the top 7 bits of the key's hash), read eight at a time as one 64-bit word, so a lookup compares a key only in a bucket whose tag matches; it holds up to 7/8 of its buckets, and doubles when full. Its keys are any type that is Hash: integers and bool, a String, a pool.Ref[T], a struct that declares is Hash (the compiler supplies its hash from its fields, and the struct writes the == that goes with it); a float key is refused. A key moves in and the dictionary owns it.

import stdio use *;
import collections use *;

fn main() i32 {
  mut counts = new Dict[String, i64];
  imm words = ["to", "be", "or", "not", "to", "be"];
  each w in words {
    *counts.getOrInsert(String.from(*w), 0i64) += 1i64;   // one search; the String moves in
  }
  print <- counts.len();
  print <- "\n";
  print <- *counts["be"];                          // a &str looks up a Dict[String, V]
  print <- "\n";
  if counts.contains("not") { print <- "has not\n"; }
  match counts.get("or") {
    case imm n Some {print <- *n; print <- "\n";}
    case is None {print <- "none\n";}
  }
  match counts.remove("to") {                      // the value comes out
    case imm n Some {print <- n; print <- "\n";}
    case is None {print <- "none\n";}
  }
  print <- counts.len();
  print <- "\n";
  0i32;
}

This prints 4, 2, has not, 1, 2 and 3, one to a line.

Looking things up

Lookups take a &K: get(&k) is an Option of a borrow of the value, getMut a mutable one, getCopy an Option of a copy (only where the value copies, which is the lookup that works through a shared Rc[mut, Dict[K, V]]), contains, remove (the value moved out, the key finalized), d[&k] and &mut d[&k] (a panic for a key it does not hold), insert(k, v) (when it replaced an entry, finalizing the old key, an Option holding the old value moved out to the caller, as Rust's does, and None for a new key; the value dies with the caller's binding, or at the end of a statement that ignores it; d <- k: v ignores it), getOrInsert(k, v) (a mutable borrow of the value held, or else v moved in, with one search: *counts.getOrInsert(word, 0) += 1), clear, len and capacity (the entries it holds before it grows).

Text keys looked up as &str

A Dict[String, V], a Dict[So[str], V] or a Dict[Rc[str], V] (an owner of text is Hash, an immutable key with no spare capacity; a literal given to insert is copied into the owner) also takes the key as the body it lends or holds, a &str (d.contains("core")), for every one of these lookups: a literal, a view (s.view(), a slice of text), a So[str] and an Rc[str] are each lent as a &str, so none builds a String to ask. They find the key they equal because a str, a String and a literal feed a hasher the same bytes (str has a hash of its own) and == compares the bytes. A d["sdl"] of a key it does not hold is a panic that names the key; one by a &K does not. A &Array[u8] is not text until it says so: bytes as &str.

Visiting order and seeds

A dictionary is unordered: each dictionary keeps a seed of its own, the process's random one by default, so keys(), values() and entries() (cursors, each next() giving an Option of a borrow, the dictionary loaned while one is used) visit in a different order on every run, and a program sorts, or looks a key up, rather than rely on it. Dict[K, V].deterministic() fixes the seed, and then the same keys inserted in the same order are visited in the same order on every run; Dict[K, V].withSeed(n) takes one of your own. When the order matters to the output, use an OrderedDict, a Dict that visits in the order of insertion, with the same methods under the same names.

Set

Set[T] is a set of any type that is Hash: a Dict whose values take no bytes, so it has the dictionary's table, seed and unordered visiting. insert(x) answers whether x was new (a held element stays, and the item given dies), contains(&x), remove(&x) (true when it was held), clear, len, isEmpty, capacity, deterministic() and withSeed(n); items() is a cursor over borrows of the elements. A Set[String] takes an element as the &str a String lends (s.contains("core")).

import stdio use *;
import collections use *;

fn main() i32 {
  mut seen = new Set[String];
  imm words = ["to", "be", "or", "not", "to", "be"];
  mut repeats = 0;
  each w in words {
    if not seen.insert(String.from(*w)) {      // insert answers whether the element was new
      repeats += 1;
    }
  }
  print <- seen.len();
  print <- " distinct, ";
  print <- repeats;
  print <- " repeats\n";
  if seen.contains("or") { print <- "or is in\n"; }
  if seen.remove("or") { print <- "or removed\n"; }
  if not seen.contains("or") { print <- "or is out\n"; }
  0i32;
}

This prints 4 distinct, 2 repeats, then or is in, or removed and or is out.

Deque

Deque[T] is a double-ended queue, a growable ring buffer (Rust's VecDeque): its values are in one block, as a circle, the first at a slot that moves, so push and pop at the back and pushFront and popFront at the front are all O(1), where a List can take a value off its front only by moving every other one. peek() and peekFront() are an Option of a borrow of the last and the first value, get(i) the same of position i counted from the front (None past the end), d[i] and &mut d[i] borrow it (a panic past the end), and items() is a cursor over borrows from the front to the back.

import stdio use *;
import collections use *;

fn main() i32 {
  mut line = Deque[i32].empty();
  line.push(1);
  line.push(2);
  line.push(3);
  line.pushFront(0);                  // O(1) at the front too
  match line.popFront() {
    case imm v Some {print <- v; print <- "\n";}
    case is None {print <- "empty\n";}
  }
  match line.peek() {                 // the last, as a borrow
    case imm v Some {print <- *v; print <- "\n";}
    case is None {print <- "empty\n";}
  }
  print <- *line[1usize];             // counted from the front
  print <- "\n";
  each v in line {
    print <- *v;
    print <- " ";
  }
  print <- "\n";
  0i32;
}

This prints 0, 3, 2 and 1 2 3.

A full block is replaced by one twice the size (4, 8, 16, ...), the values moved in order with the first in slot 0; it never shrinks. reserve(n), capacity, clear (finalizing front to back, keeping the block), len, isEmpty and new Deque[T](n), a block of exactly n slots, are a list's. Its values may wrap round the block's end, so it has no view(): read them by position or with the cursor.

OrderedDict

OrderedDict[K, V] is a Dict that visits in the order of insertion, on every run and under every seed, which is what a program wants to print, write out as a file, or replay (a JSON object, a configuration, HTTP headers). It has the same methods under the same names, including the &str lookups of an OrderedDict[String, V] and the cursors keys(), values() and entries(), and the same seeds.

import stdio use *;
import collections use *;

fn main() i32 {
  mut headers = new OrderedDict[String, String];
  headers <- String.from("Host"): String.from("example.org");
  headers <- String.from("Accept"): String.from("text/html");
  headers <- String.from("Host"): String.from("cone.dev");   // replaced where it stands
  each key, value in headers {
    print <- key.view();
    print <- ": ";
    print <- value.view();
    print <- "\n";
  }
  headers.remove("Host");                                    // the later entries move down
  headers <- String.from("Host"): String.from("again");      // a key put back goes last
  each key in headers.keys() {
    print <- key.view();
    print <- "\n";
  }
  0i32;
}

This prints Host: cone.dev, Accept: text/html, then Accept and Host.

Its layout is Python's compact dict and Rust's IndexMap: a dense array of (hash, key, value) in insertion order, which the cursors walk front to back, and beside it an index with the same control bytes and eight-at-a-time probe as Dict's, holding for each bucket a u32 position in the array, so a table holds fewer than 232 entries. A lookup is one memory access slower than Dict's; iteration is faster, with no empty buckets to skip. Inserting a key it holds replaces that entry where it stands; a key put back after a remove goes to the end. remove keeps the order: every later entry moves down one place, so it costs the entries after the one removed (IndexMap's shift_remove). swapRemove(&k) is O(1) but moves the last entry into the hole, which breaks the order. If you mostly look keys up and rarely iterate, Dict is the faster choice.

String, text that grows

String is the growable string: a list of bytes, lent as text, &str, by s.view(), with the methods of text folded in as its own. A literal is copied into a String wherever one is wanted, and <- appends text or a number:

mut s = String.from("hello");
s <- ", ";                               // append text
s <- "world", 33i64;                     // and a number
s.appendByte('!');
print <- s.view();                       // hello, world33!
imm parts = String.from("a,b,c").split(',');   // copies, which are Strings

The send operator

Everything given to a collection above, and everything printed since the first program, went through <-: print <- "Hello" streams text to the output, xs <- 4 pushes onto a list, ages <- name: 31 puts a key and its value in a dictionary, and new List[i32] <- 2, 3, 5 builds a list with its contents. It is the one operator for giving values to anything that takes them.

What <- does, and its entries

A type may implement several methods that overload "<-", to "append" values to a receiver. Each such method has its own name and declares that it overloads `<-`. This can be useful for a variety of purposes:

  • Appending elements to the end of some collection, queue or string.
  • Serializing data to an output stream, such as the console.
  • Sending data to another thread/actor/machine via a channel

It is not necessary that all values appended to the receiver be data that is accumulated by the receiver. Some values could be understood to be instructional directives that alter the behavior of the receiver on the fly. For example, a directive could offer formatting, rendering or structuring instructions.

The receiver is borrowed for the append with the permission that the chosen method's self declares. A method taking self &mut, as a collection's does, needs a receiver that may be written: a mut variable or global. Held through a reference, it is the reference's permission that is checked, never the variable's, so an imm variable holding an Rc[mut, List[i32]], an Arc[mut, List[i32]] or a &mut List[i32] is appended to, while an Arc[imm, ...], a &List[i32] or an imm list is refused. A method taking self & changes nothing the receiver holds, as the methods of stdio's print do, whose data lives in the C library's stream: it is available on an imm receiver, and print is an imm global. (Moving and lending values explains borrowing.)

What follows the send operator is a list of entries, separated by commas, and each is appended in turn, as though it had an append of its own:

print <- "Hello ", user;   // equivalent to: print <- "Hello "; print <- user

Besides a value, an entry may take one of four forms, each recognized only in this list:

  • n of x appends n values, evaluating x once for each: xs <- 4 of 0. Nothing is shared between them, so a construction gives a new value each time, while a variable holding a value that moves is moved by the first and is gone for the second. The count is a usize; a constant one is from 0 through 4294967295, as an array's size is.
  • fill x appends x, evaluated once for each, until the collection is full: until its len() reaches its capacity(), the two methods it asks. A collection that declares neither cannot be filled.
  • k: v appends a key and its value together, through a <- method that takes the two: ages <- name: 31. Appended in order, a later value for a key the dictionary already holds replaces the earlier.
  • each draws values from a source, one at a time: each src appends every item of src (an item a loop would lend as a borrow is appended as a copy of it), and each x in src if cond yield v is a loop's own header (below), the yield giving what is appended on each pass. yield k: v appends a pair. The source may be anything each walks, a number range included. With parallel before the each the passes run at the same time and the values are joined in the order of the passes, into a List only (The parallel builder).
mut xs = new List[i32];
xs <- 1, 2, 3 of 0;          // 1, 2, 0, 0, 0
xs <- fill -1;                // -1 until xs.len() is xs.capacity()
tx <- job, 2 of next();       // a channel's '<-' sends each
imm copy = new List[i32] <- each xs;                          // every item of xs
imm evens = new List[i32] <- each x in xs if x % 2 == 0 yield x * 10;
imm older = new Dict[i32, i32] <- each id, age in ages yield *id: age + 1;
imm tens = new List[i32] <- each xs.iter().filter(x => *x > 2).map(x => *x * 10);   // a chain of adapters
xs <- 9, each other.drain(), 8;      // items that move are handed over, not copied
imm doubled = new List[i32] <- parallel each x in xs yield x * 2;   // at the same time, in order

The loop reads its source while the list is appended to, so the two may not be the same list: xs <- each xs is refused as each x in xs { xs.push(*x); } is, since the list could move what the loop is reading. An array's contents may not use each: its size is fixed, and a loop's count is not known when it is compiled.

The words of and fill mean this only in the list; elsewhere they are ordinary names. In the list, fill is the word when a space and then a value follow it, so fill(3) still calls a function and xs <- fill; still appends a variable named fill.

The list runs to the end of the statement, across as many lines as it needs. Inside another comma-separated list, such as a call's arguments, a construction's contents (below) take one entry, and several are parenthesized: draw(new List[i32] <- (1, 2), x).

Inside a with block, <- with nothing on its left appends to this ('<-' Prefix Operator). A negative value after a comparison pattern's < needs a space, case < -1, since <- is this operator.

Building one collection from another

A collection's contents

A construction may be followed by <- and a list. The value is built by its init, whose arguments the parentheses carry, such as a capacity; then each entry is appended to it; and the whole is the value built:

imm primes = new List[i32] <- 2, 3, 5, 7;
imm zeros = new List[f32](100) <- fill 0.0;     // room for 100, then filled
imm ages = new Dict[String, i32] <- String.from("Ann"): 31, String.from("Bo"): 12;

An array has no init and no <-, and its size is fixed, so its construction is its contents, which fill it exactly: new Array[f32, 4] <- fill 0.0. Written with several sizes, its entries are its scalars, row by row: new Array[i32, 2, 3] <- 1, 2, 3, 4, 5, 6.

An allocation is a construction too, and takes contents the same way. An array's fill it in the region's memory, an element at a time; a collection's are appended through the new reference:

imm grid = new Rc[mut, Array[f32, 4]] <- fill 0.0;
imm names = new Rc[mut, List[i32]](10) <- 1, 2, 3;

each inside <-: <- each … if … yield

An each may stand in the list after the send operator (above), beside values, of, fill and pairs. With only a source it drains it: every item is appended. With variables it is the loop's own header, including the if filter, and a yield in the place of a block says what each pass appends:

imm copy = new List[i32] <- each other;                     // every item of other
imm big = new List[i32] <- each x in other if x > 9 yield *x;
imm squares = new List[i32] <- each i in 1 .. 5 yield i * i;    // 1 4 9 16 25
imm index = new Dict[i32, str] <- each p in people yield p.id: p.name;
xs <- 0, each x in other yield x + 1, 99;               // in the middle of a list
imm tens = new List[i32] <- each other.iter().filter(x => *x > 2).map(x => *x * 10);   // a chain

This yield belongs to the entry: it is not a generator's, which is a statement of its own, so a generator may build a list this way and then hand values to its caller. Two or more variables unpack a tuple item as they do in a loop, and yield k: v appends a pair to a collection that takes a key and a value. The items an each gives of a collection are borrows, so a drain appends a copy of each (a type that moves is not copied: drain a source that hands its items over, each other.drain()), and a yield writes the * itself where it wants the value. The list being appended to cannot be the source: xs <- each xs is refused, as pushing to a list while a loop walks it is. An array's contents cannot hold an each, as its size is fixed.

The source may be a chain of adapters, in the bare form or after in in the header form: the chain is a cursor, and the entry walks it as any other, one loop. A chain that starts at a list's iter() hands out borrows, so the items are copied as from the list itself; a chain whose closure makes the value (map(s => String.from(s.view()))) hands the value over; and one that starts at drain() moves the items out of the list, those a filter rejects are dropped, and the list is left empty:

imm lengths = new List[usize] <- each names.drain().map(s => s.len);      // names is left empty
imm kept = new List[i32] <- each v in xs.iter().map(x => *x * 2) if v > 6 yield v + 1;
imm squares = new Dict[i32, i32] <- each k, v in xs.iter().map(x => (*x, *x * *x)) yield k: v;

A chain that starts at the list being appended to is refused as xs <- each xs is (xs <- each xs.iter().map(f), and with drain()). A chain whose closure reads the list while it grows (its len, an item's value) is allowed. A dictionary takes pairs by yield k: v in the header form; the bare form new Dict[K, V] <- each pairs is not built for any source. new List[T] <- parallel each chain is refused: a chain cannot be split (on its own page).

A cursor whose next names no lifetime lends: each item is a borrow of the cursor itself, gone at the next step. A chain over one feeds the entry the same way when each entry is a value made from the item (a number copied, map(x => *x + 1), a field read). A list that would keep the lent items themselves (of a struct holding the borrow) is refused, whatever adapters sit in the chain.

Walking a collection

Walking a collection is each. A List is walked as the slice it lends, a counted loop; iter() is its cursor, for code generic over cursors (Iterator), and the methods of Array[T] it folds in come with it: mutItems() lends each element as a &mut to change, indexed() pairs a position (a usize) with a borrow of the element, chunks(n) and mutChunks(n) hand out its values in runs of n (each run a slice, a &mut one from mutChunks, which a list gives itself), asArrays[N]() and mutArrays[N]() see them as rows of N over the same block (Seen as Rows), and drain() leaves the list empty at once (keeping its block) and hands each value over by value, finalizing those a loop left early did not reach.

import stdio use *;
import collections use *;

fn main() i32 {
  mut xs = List[i32].empty();
  xs <- 1, 2, 3, 4, 5;

  each x in xs.mutItems() {              // each element lent as a &mut
    *x = *x * 10;
  }
  each i, x in xs.indexed() {            // a position beside a borrow of the element
    print <- i;
    print <- "=";
    print <- *x;
    print <- " ";
  }
  print <- "\n";
  each run in xs.chunks(2usize) {        // runs of two; each run is a slice
    print <- run.len;
    print <- " ";
  }
  print <- "\n";
  mut ys = List[i32].empty();
  ys <- 7, 8, 9;
  each a, b in zip(&xs, &ys) {           // two collections side by side
    print <- *a + *b;
    print <- " ";
  }
  print <- "\n";
  each x in xs.drain() {                 // leaves the list empty; each value by value
    print <- x;
    print <- " ";
  }
  print <- "\n";
  print <- xs.len();
  print <- "\n";
  0i32;
}

This prints 0=10 1=20 2=30 3=40 4=50, 2 2 1, 17 28 39, 10 20 30 40 50 and 0, each on its own line.

A Deque, a Set, a Dict and an OrderedDict each have an iter() that each calls itself: a deque's and a set's give a borrow of each element (items() is the same cursor), a dictionary's gives its pairs, a borrow of the key and a borrow of the value, which each key, value in dict unpacks. The dictionaries' other views are cursors too: keys(), values() and entries() (a borrow of each entry, with its key and value). zip(&a, &b) walks two lists, arrays, slices, deques, sets or dictionaries side by side. A dictionary or set is not changed while a loop walks it, and a dictionary's order is the one described above. A String's text is walked through chars() and charIndices() (The Methods of str).

Note: Not built yet: closure iterators, and a source that runs its own loop around the body of an each.

Iterators

each supports several ways to iterate over a sequence of values:

  • Number range, for simple arithmetic progressions.
  • Array, slice or list, to work with individual elements.
  • Cursor, something with a next method, and anything that gives one. A generator is a cursor.
  • Closure, to deal with algorithmically-generated values (not built yet).

Array, Slice and List Iterators

each can be used to iterate through every element of an array, a slice or a list, one at a time. The variable is a borrow of the element (the elements themselves stay where they are, and the list is still whole afterwards). A borrowed number needs no * in an expression: it is read through on either side of an operator (x + total, total + x), on the right of a compound assignment (sum += x) and in a comparison (x > 1, or x == y for two borrows, which compares the values), and so is any value that copies freely: a bool, a char, a plain struct (Implicit De-referencing). The * is written where the value itself is wanted: a copy of the item (imm y = *x), a value handed to a function, a break or yield, or a store through a &mut:

mut sum = 0;
each x in [4, 3, 8, 2] {
  sum += x;
}

mut chars = 0usize;
each name in names {      // a List[String]: name is a &String
  chars += name.len;
}

An array or a slice is walked by a counted loop over its length, and so is a list, which lends its elements as a slice: none of them makes an iterator object, and the loop is the one a while over the indexes would be. While the loop runs the list may not be changed, since the borrows it hands out would not survive a change. For the same reason an await in the body is refused over an array or a list, whose borrow would have to last across it; over a number range it is fine (An await in a loop).

Changing items in place: mutItems

A plain each only reads. To change the items of a list, an array or a slice where they are, walk mutItems(), which lends each item as a &mut:

each x in list.mutItems() {
  *x = *x * 2;       // x is a &mut of the item
}

It is the same counted loop as a plain each over a slice. The list stays borrowed mutably while the loop runs, so nothing else may read or change it until the loop is over. A list, an array or a slice that is only read has no mutItems to take (an imm list, or a &Array[T] parameter).

A borrow written as the source, each x in &mut list, is refused, in parallel each and in <- each too, with the message to write list.mutItems(): each reads what it walks, and the change in place is a method that lends the items. each x in &list is allowed and reads, as each x in list does.

Taking items out: drain

list.drain() gives the values up one at a time, moving each out of the list into the loop's variable, which then holds the value itself (not a borrow of it), so it works for items such as a String that cannot be copied:

each name in names.drain() {   // name is a String, moved out of names
  joined.append(name.view());
}
// names is now empty (its block is kept for reuse)

The list is left empty as soon as drain is called, and may not be used while the loop runs. Each pass's value is finalized as the pass ends. A loop left early, by break or return, finalizes the values it did not reach.

Positions: indexed

indexed() of a list, an array or a slice gives each position with a borrow of its item, a pair that two variables unpack. Walked directly by each, it is a counted loop, as a plain each is:

each i, name in names.indexed() {   // i is a usize, name a borrow of the item
  print(i, name);
}

A bare indexed() always borrows its items for reading, on a &mut slice as on any other. To change them, call it on mutItems(), a cursor of its own whose indexed() lends each item as a &mut:

each i, p in buf.mutItems().indexed() {
  *p = f(i);                        // p is a &mut of the item
}

Every other cursor that declares is Iterator[T] has an indexed() too: a generator, a chain, a cursor of one's own. Its item is the same pair, the position (a usize, counted from 0 as the cursor is walked) and what the cursor gives. Positions count what the cursor wrapped gives, so after a filter they number what is left, and an indexed() before the filter keeps the original positions. A cursor that lends its items (one whose next names no lifetime, so an item is gone at the next step) still lends once numbered: the borrow is inside the pair, and every use that would keep it past the next step is refused as it is without the numbering.

each i, y in xs.iter().map(x => *x * 2).filter(y => *y > 20).indexed() {
  printInt(i64.from(i) * y);        // i counts the items the filter kept
}

Runs: chunks and mutChunks

chunks(n) of a list, an array or a slice hands out its items in runs of n, each run a slice; mutChunks(n) hands each out as a &mut slice, to change in place. The last run is what is left, so it is shorter when n does not divide the count; n larger than the count is one run of everything; an empty source has no run. n of 0 is a panic, at the line of the call. indexed() numbers the runs from 0:

each run in list.chunks(4) {              // run is a &Array[T] of 4 items (the last may be fewer)
  ...
}
each y, row in pixels.mutChunks(width).indexed() {
  each x, p in row.mutItems().indexed() { *p = shade(x, y); }
}

The cursor chunks gives has len (how many runs are left), at(k) (run number k of those left) and split(at) (the runs before run at and those from it on, each a cursor over the same items), so it is a ParallelIterable that cuts only between runs. A parallel each walks it.

For a buffer of pixels, three bytes each, mutArrays[3]() first sees it as a slice of Array[u8, 3] (Seen as Rows), so the runs are rows of pixels and a pixel's channels are indexed: each y, line in pixels.mutArrays[3]().mutChunks(width).indexed() { line[x][0] = ...; }

Two together: zip

zip(&xs, &ys) walks two lists (or deques, sets, dictionaries, or anything else with an iter method) side by side, giving a pair of what each gives, and ends when the shorter does:

each x, y in zip(&xs, &ys) {
  ...
}

An array and a slice have an iter() too (each x in a.iter() is the loop each x in a is), and zip takes them, with the & a list takes: zip(&arr, &xs), or two slice parameters, zip(s, t).

A cursor is zipped with its own method, which takes the other cursor by value (the & of the function would borrow a value that ends with the statement), so a chain goes on from it. Every cursor that declares is Iterator[T] has it (see Adapters), the cursor of a list or an array, a deque, a dictionary, a generator and a cursor of your own, as well as what chunks(n), mutChunks(n) and mutItems() give: xs.iter().zip(ys.iter()), a.mutChunks(n).zip(b.mutChunks(3usize * n)). It gives the same pairs as the function (a tuple, which each x, y unpacks), ends with the shorter, and the pairs can be mapped, filtered and counted like any items: xs.iter().zip(ys.iter()).map(p => *p.0 * *p.1).sum(). The argument is a cursor, not a collection: xs.iter().zip(ys) is refused. Its indexed() numbers the pairs from 0, three variables, the position and one item from each source. each walks it through next.

each y, ra, rb in a.mutChunks(n).zip(b.mutChunks(3usize * n)).indexed() {
  ...                          // ra is a &mut slice of n items of a, rb of 3n items of b
}
each x, y, z in a.mutChunks(n).zip(b.mutChunks(m)).zip(c.mutChunks(k)) {
  ...                          // a third cursor: a flat triple of the three
}

Iterator adapters

Every cursor that declares itself an Iterator has the steps that work on a sequence as a whole, as methods the trait shares: the cursors of the collections (xs.iter(), chunks, mutItems, indexed, a dictionary's, a deque's), a zip, text.chars(), a generator, and a struct of your own that says is Iterator[T], T being what its next gives. A step gives a cursor again; none does any work until a terminal method walks the chain once, from where the cursor is, and leaves it advanced:

imm k = 3;
imm total = xs.iter().map(x => *x * k).filter(y => *y > 9).sum();
each v in xs.iter().map(x => *x * k) {      // a step is a cursor too: each walks it
}

struct Countdown is Iterator[i64] {         // declared: it has map, filter, sum and the rest
  n i64;
  pub fn next(self &mut) Option[i64] { ... }
}
map(f)each item through f; the closure is typed from the item and its result is the new item's type
filter(f)the items f is true of; f is given a borrow of the item
take(n), skip(n)at most the first n items; all but the first n (any integer, a plain literal included; more than there are is none)
zip(other)pairs of an item from this cursor and one from other (a cursor), ending with the shorter (Two together)
fold(init, f)f(result so far, item) over the items, starting from init
any(f), all(f)whether f is true of some / every item; stops at the first that settles it; false / true for no items
count()how many items
find(f)the first item f (given a borrow) is true of, as an Option
sum(), min(), max()for number items: the total (0 for none); the smallest and largest as an Option, None for no items (the first of equals)

An item is whatever the cursor gives. A cursor that lends (xs.iter()) gives borrows, so a closure reads through them: map(x => *x * 2). A filter's closure is given a borrow of the item, a borrow of a borrow for such a cursor, which an operator reads through (filter(y => *y > 3) for either kind). sum, min and max are methods only where the items are numbers (integers, f32, f64), so a cursor that lends is mapped to values first, map(x => *x).max(), and a struct has none of them. find hands the item back, and a borrow cannot be handed back through the chain's steps (each step's next is a method whose signature names no lifetime, so its result is held to lend from the step), so it too is called on values: map(x => *x).find(y => *y == 5).

The closures are generic arguments ([F fn(x T) U]), each its own type, so a chain is compiled into one loop with every closure's body inline and no call through a pointer for any item. A closure that changes a variable (x => { n += 1; *x; }) is run once for each item the chain asks for and no more. Over a cursor that gives numbers (not a borrow), a map and a sum is vectorized as the hand-written loop is. Over a cursor that lends the loop is not vectorized, since each step answers an Option of a borrow, which is a pointer tested for null: the same loop a hand-written while over next() is.

A type with a next that does not declare is Iterator[T] is still accepted wherever an Iterator is asked for as a bound (fn f[T, I Iterator[T]](it &mut I): fitting a trait is by shape), and each walks it. What it does not get is the shared methods, which come with the declaration; asking it for map is an error that says to declare it. Each step is a cursor of its own type (the whole chain's, so a chain is held in a variable of inferred type, or walked at once). The terminal methods take the cursor by &mut, so one called on a chain made in the same expression needs no name for it.

Not built yet: a source that runs its own loop around the body of an each, taking the body as a closure, for a source that cannot hand out its items one by one (a line reader that lends each line from its own buffer, say). each would use it when the source has it, and otherwise use next; break, continue and return in the body would reach the source as signals, and an await in such a body may be refused. The parallel reductions are on their own page. A chain feeding the entries of a collection being built (<- each) is built.

Iterator and Iterable

Two more of core's traits name the shapes a sequence of values is walked by, for code that is generic over them. A type is an Iterator[T] by having next, and an Iterable[T, I] by having iter. Neither is declared: a type with the method complies, as the cursors of str and of every collection do, and so does a struct of your own.

pub trait Iterator[T] {
  pub fn next(self &mut) Option[T];     // the next value, None once there are no more
}

pub trait Iterable[T, I] where I is Iterator[T] {
  pub fn iter(self &) I;                // a cursor over what it holds, without consuming it
}

A function asks for one as a bound, decided where it is called and compiled for the type's own methods, or as a virtual reference (&<mut Iterator[i64]), which takes any cursor through one compiled function:

fn count[T, S Iterator[T]](it &mut S) usize {
  mut n = 0usize;
  while true {
    match it.next() {
      case imm v Some {n = n + 1usize;}
      case is None {break;}
    }
  }
  n;
}

fn total[S Iterator[&i64]](it &mut S) i64 { ... }   // a cursor that lends numbers
fn walk[T, I, C Iterable[T, I]](c &C) where I is Iterator[T] { ... c.iter() ... }

T is what next gives, so a cursor that lends its values (a Deque's items(), a Dict's keys()) is an Iterator[&V]. The &V of a bound names no lifetime, and a cursor whose next returns the lifetime its own struct declares (Option[&'a V]) meets it, as a method with no other parameter has nothing to store through its receiver. The cursor's own signature is what a bound's call reads, so borrows given by two calls of next may be held together; through a virtual reference the trait's signature is read, which ties a result to the whole cursor. Iterable takes its cursor's type as a second argument, I, because a trait cannot yet name a type its implementer chooses; both arguments are found from the type passed. A type with no next (or iter), or with one that gives another type, is refused where the function is called.

Fitting is by shape, and the trait's shared methods come with the declaration. A type that says struct Countdown is Iterator[i64] has, beside its own next, the steps that work on a whole sequence, map, filter, take, skip, fold, any, all, count, find, sum, min and max (Each and Iteration), which the trait writes once as generic defaults. A type with a next and no declaration meets a bound on the trait all the same and has none of them. A generic default has no slot behind a virtual reference (&<mut Iterator[i64] calls next), and a default that exists only where a condition holds (sum wants number items) has none either.

Under the collections: arrays and slices

Note: Not implemented: a subslice's count form (,), an index relative to the end ($-), a slice made from a reference or a pointer, and copying and filling a range of elements. A borrowed array or string literal (&[1, 2, 3], &"Padma") is not yet a slice: it is a reference to the array, with no .len of its own. Making text from bytes, bytes as &str, does not yet check that the bytes are UTF-8, nor that nothing still writes them while the text is used.

All of the standard collections are built on the array primitives: an array has a statically known size, and an array reference, a slice, is a borrowed view of some runtime-determined number of elements. This page used List, Dict, Set and Deque (Collections and the send operator). What follows is about the layer under them and the rest of what they offer: the slice, which lets one function work on any run of elements; OrderedDict; freezing a list into an owner; the small traits that let a function ask for exactly the ability of a collection it uses; and why a push waits for a borrow of an element.

Slices: borrowed views of elements

An array reference, or slice, is a borrowed view of some number of elements of the same type, laid out one after another in memory. How many there are is known only at runtime, so the reference carries the count alongside the pointer to the first element. A slice does not own its elements: it is borrowed from something that does, and like any borrowed reference it may not outlive it.

Owned Arrays

The body of a run-time length is Array[T], the array type without a size. It has no size of its own, so it is held only through a reference that carries the count, and the slice is its borrow: &Array[T] is the slice, and &mut Array[T] the slice that changes its elements; the earlier spelling, &[]T, is refused. Every array reference is borrowed. There is no owning array reference: a managed reference is thin, virtual, or fat with the count of a dynamically sized body, str or Array[T], never an array reference. A slice of bytes, &Array[u8], and a borrow of the text body, &str, are the same pair of words and different types, and either converts to the other with as. What owns an array is one of these:

  • A fixed-size array, whose size is part of its type. It may be held in a variable or a field, or allocated in a region and reached by a thin reference whose type carries the size. Its contents follow the allocation after <-, and fill the array in the region's memory, with no array made elsewhere and copied in; an array already made is moved in from the parentheses: 
    imm grid = new Rc[mut, Array[i32, 4]] <- fill 0i32;      // grid's type: Rc[mut, Array[i32, 4]]
imm made = new Rc[mut, Array[i32, 4]](new Array[i32, 4] <- 1, 2, 3, 4);
  • An owner of Array[T], when the number of elements is chosen at runtime and never changes: So[Array[T]], Rc[Array[T]], Arc[Array[T]] or Gc[Array[T]], each a pointer and a count, one hop to the elements. It is allocated by copying the elements of a slice, as an owner of str is, so only where the elements copy; a list's freeze() moves its own into one instead, any element included. The owner has len, indexes (o[i]) and takes a borrowed range (&o[a..<b]) as a slice does, and is lent as the slice wherever a &Array[T] is wanted, a generic's element type inferred from it. Which of the three kinds of list it is comes from its permission: held writable (So[Array[T]], Rc[mut, Array[T]]) its elements change but its length does not; held imm (Rc[imm, Array[T]], Arc[imm, Array[T]]) nothing changes. A borrow of a fixed-size array, &Array[T, n], converts to the slice. 
    imm primes = new Array[i32, 4] <- 2, 3, 5, 7;
imm shared = new Rc[imm, Array[i32]](&primes);     // a copy: a pointer and a count
imm total = sum(shared);                           // lent as the &Array[i32] sum takes
imm frozen = list.freeze();                        // a List[T]'s block, moved into a So[Array[T]]
  • A collection, when the number of elements is chosen at runtime. An array whose whole length is decided at runtime, and which may grow or shrink, is exactly what a collection is: a List holds a pointer to its elements, how many there are, and how many it has room for. A list held in a local is used directly; one that several owners share is a managed reference to it: 
    imm names = new List[i32] <- 3;
imm shared = new Rc[mut, List[i32]](names);     // names is moved in; shared's type: Rc[mut, List[i32]]

The length of a shared list lives once, in the list, where every owner sees the same count. A length carried in each copy of a reference could not stay in step when the list grows. Writing +[], as a type or an allocation, is an error that says this.

Borrowing a Slice

A slice may be borrowed from any array, from another slice, or from a collection that lends one:

imm nbrSlice = &[1, 2, 3];
imm textSlice = &"Padma";
imm listSlice = list.view();    // from a List
imm fillSlice = list.viewMut(); // from a List, its elements changeable: &mut Array[T]
imm uniSlice = (&uni list).viewUni(); // from a List lent &uni: &uni Array[T]

These slices point to all elements of the source's array. (The first two borrow a literal: see below for how that differs from a slice made with &[].)

If a static array is passed as a call argument where a slice is expected, it is automatically converted into a slice:

print("abc");    // equivalent to print(&"abc")

Safety Note: Because a slice is a borrowed reference, its lifetime is limited, ensuring it can never outlive the source array it provides a view into. Depending on permissions, it may temporarily lock out access to the variable it borrows from, thereby ensuring the original array cannot be moved or resized while the slice is active.

Borrowing a Literal or a Constant

A literal whose elements are all constants, an array literal or a string literal, is kept in read-only memory, and so is a named constant holding an array literal or the byte array a string literal fills. A borrow of one is a constant too: it lives as long as the program, so a function may return it, and it may not be mut.

Written &[1, 2, 3] or &"Padma", the borrow is a reference to the array (&Array[i32, 3]). It is taken wherever a slice is wanted, but it has no .len of its own. &[][1, 2, 3] is the slice, with one:

const primes Array[u32, 4] = [2u32, 3u32, 5u32, 7u32];

fn firstOf(p &Array[u32]) u32 { p[0]; }
fn smalls() &Array[i32] { &[1, 2, 3]; }       // the borrow outlives the call

imm nums &Array[i32, 3] = &[1, 2, 3];        // a reference to the array: nums.len is refused
imm sl &Array[i32] = &[][1, 2, 3];           // the slice: sl.len is 3
imm two = firstOf(&primes);                 // a named constant, borrowed: 2
Borrowing a Computed Literal

An array literal with a computed element, such as &[x, y], is a temporary. It lives to the end of its statement, or, where a variable's initializer borrows it, to the end of the block (see borrowing a temporary). A borrow of it cannot be returned from the function:

imm s = &[][x, y];                  // lives to the end of the block
imm t = total(&[x, y, 6]);          // lives to the end of the statement
Subslices

It is also possible to create a new slice that points to some subset of the elements in some array or slice. This is accomplished by indexing using a range operator between two unsigned integers:

  • .. includes the last specified element.
  • ..< stops before the last specified element.
  • , specifies how many elements are in the slice.

The two range operators are the ones a number range of each and a range pattern use. For example:

imm x = &"Abcd"[1..<3];   // a slice pointing to "bc"
imm y = &"Abcd"[1..3];    // a slice pointing to "bcd"
imm z = &"Abcd"[2, 1];  // a slice pointing to "c"

If either index integer is unspecified, 0 and end are assumed (so [..3] is the elements 0 through 3, [..<3] the first three, and [1..] everything from 1 on). A range is checked against the length of what it is taken from, as an index is: its start may not come after its end, nor its end after the last element. The subslice has the permission and lifetime a borrowed reference to one of those elements would have.

imm r = &y[1..];        // a slice pointing to "cd" (end assumed)
imm s = &y[..];         // a slice pointing to "bcd" (0 and end assumed)

An index integer may be specified relative to the last element:

imm r = &y[$-2..];      // a slice pointing to "cd"

A slice may also be created from a regular reference or a pointer:

imm slice1 = &ref[..];      // Slice count from reference is always 1
imm slice2 = &ptr[0..5];

Operations

Slices may be indexed, copied, compared, iterated over, and queried for their properties. Many of these operations work the same way they do with static arrays. A slice, and an array, calls the methods of core's Array[T]: iter(), indexed(), mutItems() (a &mut slice's, for changing elements in place), chunks(n) and mutChunks(n) (the elements in runs of n, each run a slice, a &mut one from mutChunks), which each walks.

Access an Element

A single element within an array may be accessed using an unsigned integer value enclosed in square brackets. This supports both getting and setting the values at a specific index:

c_array[3] = c_array[2];    // the 4th element is now the same as the third

Indexing is automatically bounds-checked by its known size. An index out of bounds is a panic naming the index, the size and the line; so is a range, &s[a..<b], that starts after it ends or ends past the size.

Borrowed Reference to an Element

One can create a borrowed reference to any element of a slice in the same way as for an static array:

imm nbrRef = &nbrSlice[1];     // points to 2
imm charRef = &textSlice[2];   // points to 'd'

Borrowing a reference to a single element is not a slice. It is just a regular borrowed reference to some value.

Copy or Fill Elements

Multiple elements of an array may be copied into another array using a range in square brackets. Both content segments must have the same type and size.

arrref[1 by 2] = sliceref[0 by 2];
greetings[n by 5] = "Kevin";

Similarly, a single value can be repeatedly filled into a slice's elements:

arrref[1 ..< 3] = 2;
Iteration

The each loop may iterate over a slice's elements:

mut sum = 0;
each x in intslice {      // x borrows each element
    sum += x;
}

Each pass's variable is a borrow of the element, which cannot be changed through it. Walking mutItems() instead lends each element as a &mut to change it where it lies, and indexed() pairs each element with its position:

each x in mutslice.mutItems() {
    *x = *x + 1;
}
each i, x in intslice.indexed() {      // i is a usize
    sum += i32.from(i) * x;
}

Both are counted loops over the slice, as the plain each is (Each and Iteration). A bare indexed() lends & on any slice, a &mut one too; mutslice.mutItems().indexed() lends each element as a &mut. chunks(n) and mutChunks(n) hand the elements out in runs of n, each run a slice (the last is what is left; n of 0 is a panic), and a parallel each gives each pass a run of its own:

each run in intslice.chunks(4) { ... }          // run is a slice of up to 4 elements
each y, row in mutslice.mutChunks(w).indexed() {
    row[0] = y;                                  // row is a &mut slice
}
Seen as Rows: asArrays

asArrays[N]() sees a slice of T as a slice of Array[T, N] over the same memory: nothing is copied, and element k of row i is element i * N + k of the slice. N is a number parameter written in brackets, since no argument says it. mutArrays[N]() is the same on a &mut slice and gives a &mut one, so writing a row's element changes the original (it has a name of its own, as mutChunks has beside chunks). Both are methods of an array, a slice and a list. A count that is not a multiple of N, and an N of 0, are a panic at the line of the call.

imm bytes = &[][1u8, 2u8, 3u8, 4u8, 5u8, 6u8];
imm rows = bytes.asArrays[3]();      // &Array[Array[u8, 3]]: [1 2 3] [4 5 6]
imm c = rows[1][2];                  // 6
pixels.mutArrays[3]()[0][1] = 9u8; // changes pixels[1]

The rows are a slice like any other, so the runs cursors cut them: a picture of bytes, three to a pixel, is written a row to a pass, a pixel's channels by index, and leaves the bytes the same loop leaves when it computes x * 3 + k itself:

parallel each y, line in pixels.mutArrays[3]().mutChunks(width).indexed() {
    each x in 0usize ..< width {
        line[x][0] = red(x, y);
        line[x][1] = green(x, y);
        line[x][2] = blue(x, y);
    }
}
Comparison

Two slices may be compared for identity with === (or !==), so long as they have the same type. This comparison checks for equality of both the starting pointer and the element count, so it asks whether the two view the same elements, not whether their elements are equal.

if slice1 === slice2 {
   ....
}

As with other references, == (or !=) on two slices compares what they refer to, element by element. Two slices are equal when they have the same number of elements and each element is == to the element at the same index in the other. Each pair is compared with the element type's own ==: a number's or a bool's, or one a struct declares; a slice of slices compares each inner slice the same way. Floating point elements compare as floating point numbers do, so a NaN is not equal to any element, itself included, and -0.0 is equal to 0.0. A slice whose element type has no == cannot be compared this way.

imm name &Array[u8] = "Padma";
if name == "Padma" {   // true: the same five bytes
   ....
}

What a slice is compared with may be anything that would be accepted where that slice is wanted: another slice, an array or a reference to one, or a string literal. An array or a reference to one may be on the left too.

Comparing for order (e.g., <) is not possible directly. One can of course compare the component parts of a slice separately.

Property Queries

A slice is a "fat" reference, as it holds two pieces of information:

  • a pointer to the first element of the array
  • an unsigned integer specifying how many elements are in the array

The component parts of a slice can be obtained:

imm ptr = array.ptr;     // The pointer to the first element
imm len = array.len;     // The number of elements

Collection Types

A collection type owns its elements and lends them out. A List keeps its elements in one block of memory it allocates and grows itself, reached through a pointer beside its count and its capacity, and lends them as a slice (view()). It defines operator methods (such as indexing), so that it behaves very much like an array.

The collection traits

The collections package also declares five small traits, one for each thing a collection can do, so that a function asks for exactly the ability it uses; each is met structurally (Traits), by having the methods, so none of the collections declares one.

  • Collection (len, isEmpty: List, Deque, String, Dict, OrderedDict, Set);
  • Indexed[T] (get(i): List, Deque);
  • Stack[T] (push and pop at the back, peek: List, Deque);
  • Queue[T] (push at the back, popFront: Deque);
  • Map[K, V] (get, insert, remove, contains by a &K: Dict, OrderedDict).

A function asks for one as a static bound (A generic trait as a constraint), fn drain[S Stack[i64]](s &mut S), fn drain[T, S Stack[T]](s &mut S) or fn drain[T, S](s &mut S) where S is Stack[T], called with &mut list or &mut deque; the bound is decided where the function is called, so the call is to the type's own methods. A trait is given all its type arguments ([S Stack] is refused), while Collection, which has none, is written alone, fn count[C Collection](c &C). The other form is a virtual reference, fn drain(s &<mut Stack[i64]), which takes the same arguments through one compiled function and a table of methods, for a value whose type is not known where the function is compiled; every trait works either way. Map's insert answers the old value, an Option (None for a new key). A Set's insert answers whether the element was new.

import stdio use *;
import collections use *;

// A function asks for exactly the ability it uses
fn countOf[C Collection](c &C) usize { c.len(); }

fn drainSum[S Stack[i64]](s &mut S) i64 {
  mut total = 0i64;
  while true {
    match s.pop() {
      case imm v Some {total = total + v;}
      case is None {break;}
    }
  }
  total;
}

// The other form: one compiled function, called through a table of methods
fn peekTop(s &<mut Stack[i64]) i64 {
  match s.peek() {
    case imm v Some {*v;}
    case is None {-1i64;}
  }
}

fn main() i32 {
  mut list = List[i64].empty();
  list <- 1i64, 2i64, 3i64;
  mut deque = Deque[i64].empty();
  deque <- 10i64, 20i64;
  imm word = String.from("four");
  print <- countOf(&list);              // a List is a Collection
  print <- " ";
  print <- countOf(&deque);
  print <- " ";
  print <- countOf(&word);
  print <- "\n";
  print <- peekTop(&mut list);
  print <- "\n";
  print <- drainSum(&mut list);         // a List is a Stack
  print <- " ";
  print <- drainSum(&mut deque);        // so is a Deque
  print <- "\n";
  0i32;
}

This prints 3 2 4, 3 and 6 30.

Fine-tuning

Rarely needed: a list a C function fills, why a push waits for a borrow, and cursors of your own.

A list that a C function fills

A list that a C function fills (the "ask how many, then fill" shape of Vulkan's queries) needs no unsafe code: list.resize(n, zero) makes it n copies of a value long (or drops the values past n), the C function is handed list.viewMut() (as a pointer, list.viewMut() as *T, and the count), and list.truncate(written) cuts it to the count C wrote, finalizing the values it drops (a no-op when written is not less than its length). resize exists only where T copies; a list of values with finalizers is shortened with truncate. Here a Cone function stands in for the C one:

import stdio use *;
import collections use *;

// Stands in for a C function that fills at most out.len values and says how many it wrote
fn squares(out &mut Array[i32]) usize {
  mut n = 0usize;
  while n < out.len and n < 5usize {
    out[n] = i32.from(n) * i32.from(n);
    n = n + 1usize;
  }
  n;
}

fn main() i32 {
  mut xs = List[i32].empty();
  xs.resize(8usize, 0);                 // room to fill: eight zeros
  imm written = squares(xs.viewMut());
  xs.truncate(written);                 // keep only what was written
  print <- xs.len();
  print <- ": ";
  each x in xs {
    print <- *x;
    print <- " ";
  }
  print <- "\n";
  0i32;
}

This prints 5: 0 1 4 9 16.

Why a push waits for a borrow of an element

A collection's elements sit in one block, and a push may move every one of them to a bigger block. So a borrow of an element (list[i], dict[key], s.view()) keeps a local collection loaned while it is used: it may be read, but a push waits for the borrow's last use. The compiler refuses the push that would leave the borrow dangling:

mut list = List[i32].empty();
list.push(10);
list.push(20);
imm first = list[0usize];     // borrows list, read-only
imm n = list.len();           // fine: the list may be read
list.push(30);                // refused: first is used again below
print <- *first;

Copying what is needed out before the push leaves no borrow to wait for (imm firstX = l[0usize].x; l.push(p);). A mutable borrow (&mut list[i], or list.viewMut(), a &mut Array[T] of every element, and a String's s.viewMut() of its bytes) is one more alias of the elements: until its last use the collection may still be read and written in place, but not reshaped, by a push, a clear or a pop.

mut list = List[i32].empty();
list.push(10);
list.push(20);
imm e = &mut list[0usize];
imm n = list.len();           // fine: read while the mutable borrow is live
list.set(1usize, 5);          // fine: written in place
*e = 7;                       // the last use of e

Each collection declares ShapeChanging (a provisional name), as does any type the compiler finds to be one from its methods, a struct wrapping a list included:

struct Pt { pub x i32; pub y i32; }

struct Bag {
  items List[Pt];
  fn first(self &) &Pt { items[0usize]; }
  fn add(self &mut, p Pt) { items.push(p); }
}

fn g(bag &mut Bag) i32 {
  imm e = bag.first();
  bag.add(new Pt(5, 6));      // refused: e is used again below
  e.x;
}

Reached through a shared path, a &mut List parameter say, the same path is frozen the same way, and a push, a clear or a pop through another reference to the same collection, or by a call that might make one, is refused while the borrow is still to be used (fn f(l &mut List[Pt], p Pt) i32 { imm e = l[0usize]; l.push(p); e.x; } is refused at the push, as is a cursor held across a push: mut it = dq.items(); dq.push(9); it.next();). The full rules, for locals, fields, and what a call could do, are those of borrowed references.

Cursor Iterators

A cursor is anything with a next method that answers an optional value, Some with the next item or None when there are no more. A type needs no declaration to be one, only the method (it is met by shape, as Iterator in the core library names, which is what generic code asks for):

struct Countdown {
  n i32;

  pub fn next(self &mut) Option[i32] {
    if n <= 0 { return None[i32]; }
    imm v = n;
    n = n - 1;
    Some[i32](v);
  }
}

mut countdown = new Countdown(3);
mut digits = 0;
each n in countdown {     // iterates: 3 2 1
  digits = digits * 10 + n;
}

The cursor is used as it is: a cursor in a variable is advanced there, so a loop left with break can be followed by another that carries on from where it stopped. A cursor that lends (a deque's items(), say) gives borrows of its items, as an array does; one that gives values gives the values themselves. An item that moves (a String the cursor hands out) is taken out of the optional value by the one variable, and is the variable's from then on; several variables, which would take the elements of a moving pair out one by one, are refused.

Something that gives a cursor

A value with no next but an iter method, which gives a cursor, is walked through the cursor it gives, as if the loop had called iter itself:

each x in collection {  // equivalent to: each x in collection.iter()
}

The collections give cursors in this way: a deque's, a set's and the dictionaries'. Calling iter only reads the collection: it is borrowed and not consumed, and may not be changed while the loop runs. Other views of a collection are ordinary methods that answer a cursor, walked the same way: each k in dict.keys(), dict.values(), deque.items(), text.chars() (Collection Types).

Two variables

Two or more variables unpack an item that is a tuple. A dictionary's cursor gives its pairs, a borrow of the key and a borrow of the value, so

mut both = 0;
each key, value in ages {   // a Dict[i64, i64]
  both += key * value;
}

and one variable would take the pair whole (pair.0 and pair.1). A number of variables that does not match the tuple, and any number but one for an array, a slice or a list, are refused.

Closure Iterator

Not built yet: each over a closure. Closures are built, but a source for each today is a value with a next or an iter method. The closure spelling below is a sketch. Look to closures for iterator versatility. Using closure iterators, one can scan through elements in a complex collection, retrieve values from a streaming resource, algorithmically calculate a sequence of values, etc. Because closures are stateful, they can generate a new value on every call.

In order for a closure to be suitable as an iterator, it must be able to signal when it is done producing values. It typically does this by returning an optional value, with the value of None signalling when it is done, just as a cursor's next does.

In the following example, imagine a closure that starts off holding the value 12, and halves (and returns) its value on each call. When the value gets to 0, it returns None instead:

mut sum = 0;
each x in |{cnt = 12}| if cnt > 0 {Some(cnt /= 2)} else {None} {
  sum += x;
}

The value of sum at the end will be 10, as each successive call to the closure returns 6, 3, and 1. After 1, it returns None, which stops iteration.

Because it is stateful, a closure is typically single use. It is created before it is needed, used to produce values lazily, and then discarded afterward. This is because, unless its state can be independently reset, it will only ever afterward say it is out of values.
