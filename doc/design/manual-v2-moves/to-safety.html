The anonymous name _ may be used for any data segment of the struct that we don't want or need access to.

  • Default value. The default value must be a constant: a literal, null for a pointer field among them, a named constant, a constant expression computed from them (Red | Green), or a reinterpretation of one to a number or pointer type with as, such as 4096usize as *u8, or an array, struct or tuple of such constants. A variant of an enum that holds no value is one too (kind Kind = Kind.Os, next Option[i32] = None); a variant that holds a value is not. Specifying default values makes initialization of a newly created struct more convenient.

    • Opaque Types

    Sometimes it is valuable to work with types where we have no idea about the size or layout of any values of that type. This is useful when interfacing with some external system which knows the layout and size of the type's data, but is reluctant to share (or we don't really care).

    We call such types opaque, because we cannot directly view their contents. Declaring an opaque type is easy:

    struct @opaque SocketHandle;
   // don't specify any fields as part of the type
   // Methods may be defined.

    As one might expect, it is illegal for a variable or field to specify an opaque type. An opaque value cannot be created or passed around. We cannot access its fields. We cannot even determine its size.

    Where opaque types are used is when pointed-at by references or pointers. Such references can be obtained, passed around, and stored, like any reference. We can call methods on a pointed-at value of an opaque type (typically implemented by the external system that knows the data layout and can work with such values). However, we may not use pointer de-referencing to read or mutate the pointed-at value.

    Tag values

    Each variant's tag value is assigned for you, ascending from zero in declaration order. You may write a value instead, which is what lines an enum up with the constants of a library written in another language. Numbering resumes from the last value written, so only the variants that need a particular value have to say so.

    An enum may also name the integer type its tag values are laid out in. That fixes the tag's width, so a value too large for it is an error rather than a silent widening away from the layout you asked for. Without it the tag is as wide as the largest value needs — note that this follows the largest value, not the number of variants.

    enum Colors u32 {
	Red   = 0xFF0000,
	Green = 0x00FF00,
	Blue  = 0x0000FF;
}

    A tag value may be negative, as some libraries' constants are. Each value must fit the named integer type the way any integer literal must fit its type, and a negative sign counts: -4 fits i32, while its bit pattern 0xFFFFFFFC does not, and a negative value fits no unsigned type. Numbering resumes from a negative value too, counting up. An enum that names no type and holds a negative value gets the narrowest signed tag that holds every value.

    enum VkResult i32 {
	Success = 0,
	NotReady,                  // 1
	ErrorOutOfHostMemory = -1,
	ErrorOutOfDeviceMemory = -2,
	ErrorDeviceLost = -4;
}

    The tag field cannot be accessed, referenced or mutated: which variant a value holds is reached by pattern matching, and compared with ==.

    For alignment reasons it may be desirable to place the tag somewhere other than first. To do this, write an anonymous field of type tag where it should go. tag means this only where a field's type is written, so it is not a reserved word and a field may still be named tag.

    enum Aligned {
	pub wide i64;
	_ tag;

	pub struct Small {pub n i32;}
	pub struct Large {pub a i64; pub b i64;}
}

    Fine-tuning

    Rarely needed: a list a C function fills, why a push waits for a borrow, and cursors of your own.

    A list that a C function fills

    A list that a C function fills (the "ask how many, then fill" shape of Vulkan's queries) needs no unsafe code: list.resize(n, zero) makes it n copies of a value long (or drops the values past n), the C function is handed list.viewMut() (as a pointer, list.viewMut() as *T, and the count), and list.truncate(written) cuts it to the count C wrote, finalizing the values it drops (a no-op when written is not less than its length). resize exists only where T copies; a list of values with finalizers is shortened with truncate. Here a Cone function stands in for the C one:

    import stdio use *;
import collections use *;

// Stands in for a C function that fills at most out.len values and says how many it wrote
fn squares(out &mut Array[i32]) usize {
  mut n = 0usize;
  while n < out.len and n < 5usize {
    out[n] = i32.from(n) * i32.from(n);
    n = n + 1usize;
  }
  n;
}

fn main() i32 {
  mut xs = List[i32].empty();
  xs.resize(8usize, 0);                 // room to fill: eight zeros
  imm written = squares(xs.viewMut());
  xs.truncate(written);                 // keep only what was written
  print <- xs.len();
  print <- ": ";
  each x in xs {
    print <- *x;
    print <- " ";
  }
  print <- "\n";
  0i32;
}

    This prints 5: 0 1 4 9 16.

    Where the value of an if is wanted as a known type — a variable's declared type, a function's return type, the parameter it is passed to, or the field it gives a value to — each branch's value is coerced to that type. So two string literals, which are each a &str, are each taken as the slice wanted:

    imm label &Array[u8] = if orbiting {"orbit";} else {"flight";};  // each branch a &Array[u8]

    Where no type is wanted, the branches must agree on one: either the same type, or a supertype they share. The same holds for the value of a block and of a match.

    Note: A call gives its arguments their parameters' types when the function or method it calls is a single declaration that is not generic. The arguments of an overload set, such as those of print <-, a generic function's arguments, and an operator's operands are given no type, since their own types are what choose what is called: there, the branches must agree on their own, or be given a type first, as in imm s &Array[u8] = if ...;.
