It is where the packages that come with Cone live: stdio, which import stdio reaches; core, which every module imports without asking; and libc and posix, raw bindings to the C library and to the POSIX functions beyond it (the C library's own on Linux, a mapping onto the C runtime on Windows), which core rests on for malloc; and, over those two, fs (files and folders), path (paths taken apart and put together) and env (environment variables), written over ISO C and POSIX. What is Windows-only beneath them is posix's: on Windows its POSIX names map onto the Windows C runtime, and its folder listing (opendir, readdir) and lstat are written over the runtime's _findfirst64 (on Linux they are the C library's); path reads the paths of the system it is built for (Windows' drive letters, shares and both separators, or POSIX's /). Beside them, process runs a program and waits for it (its arguments, a working folder, a time limit; its exit code and what it wrote to standard output and standard error, captured apart): its interface belongs to no one system, its insides are written over kernel32 (CreateProcessW, pipes, a job object) on Windows and over posix_spawn on Linux, since neither ISO C nor POSIX alone can do it on both.
