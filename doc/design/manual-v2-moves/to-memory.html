• Permission. The actual permission that governs field access is derived from both the field's and struct's permissions using a mechanism called viewpoint adaptation. If unspecified, mut is assumed, which effectively means the struct value's permission governs access.
    • Such a struct moves, as any struct with a field that moves does (move semantics), without declaring is Move. So does an enum with a variant that holds a List of the enum, and each of two types that hold a List of the other.

    A construction fills its value where it goes: declaring a variable with one hands the initializer the variable's own memory, so no copy is made.

    A construction fills its value in place, where the value goes. Declaring a variable with a construction hands the initializer the variable's own memory, and allocating one hands it the memory the region obtained; a value constructed where it has no place yet, as an argument to a function, or a field of another construction, is built in a temporary and copied there.

    The most significant restriction is that it is not possible to allocate a zero-sized value on the heap, which means you cannot create an owning reference to a value of an empty struct.

    A method that asks for its owner

    A method may also ask for the owner of its type: a borrow of an owner, written self &So[Self], self &Rc[Self], self &Arc[Self] or the borrow of any other owning reference to the type. Such a method is found only through an owner of that kind, which is borrowed for the call and is still the caller's afterwards; a plain value, a borrow or an owner of another kind has no such method, just as for any method that does not accept the receiver. It is tried after the ordinary selection, so a type's other methods are unaffected. Inside the method self reads through the owner to the value, so self.n is the field, and the owner itself is what the method can hand on or inspect (as str's cstr() does, which needs the owner's zero after the text: C Strings).

    struct Node {
  n i64;
  pub fn viaSo(self &So[Node]) i64 { self.n + 1; }   // only an So[Node] has this method
  pub fn plain(self &) i64 { n; }                    // any Node, however held
}
imm a = new So[Node](10);
imm x = a.viaSo();                                   // 11; the So is borrowed, 'a' is still ours
imm y = Node(10).viaSo();                            // **ERROR** a Node value is no owner

    A temporary is a value an expression produces that nothing takes: it is not bound to a variable, stored in a field or element, passed by value, returned or moved. A call's result whose field is read, an owning reference read through, an owner lent to a call as a borrowed reference, a value thrown away by a statement: each is a temporary, and dies at the end of the statement that produced it, the newest first, as locals die at the end of their block. A temporary produced by the condition of an if or a while dies once the condition is decided, before the branch runs, so each pass of a loop finalizes its own; and one produced by the right operand of and or or, which runs on some paths only, dies at the end of that operand. A value moved out of a temporary owner belongs to its new holder, and the owner's memory is freed without it, as above.

    imm n = open(name).length;   // the file open returns is closed here, once its length is read
take(open(name));            // moved: take closes it
if open(name).length > 0 {   // closed here, before the branch runs
  ...
}

    A temporary a variable's initializer borrows lives longer, to the end of the block the variable is declared in, as Rust extends it: so the borrow is good for as long as the variable can be used. That is a temporary the initializer borrows directly (&make()), a part of one (&make().x), what a temporary owner owns (&*makeOwner()), or a temporary owner the initializer lends where a borrowed reference is declared (imm r &R = makeOwner()), whether the borrow is the whole initializer or an element of a tuple, an array or a variant literal it builds ((&make(), 1), Some[&R](&make())), or the value of a block, of an if's arm or of a match's arm in one of those places (if c { &make(); } else { &other(); }), as Rust 2024 extends them. Such a temporary dies at the end of its block, with the block's locals, the latest first; one an arm makes, only where that arm ran. A temporary passed to a function, or a method's receiver, is not extended, even in an initializer: it dies at the end of its statement, and a variable still holding a borrow of it may not be used after that. A borrow of a temporary anywhere else (show(&make())) points at it until then.

    imm r = &make();             // the temporary lives to the end of the block
imm s &R = makeOwner();       // so does the owner, and what it owns
imm t = pick(makeOwner());    // the owner dies here: t may not be used after this statement

    A temporary that a raw pointer made from it may outlive is not finalized at all. Nothing follows a raw pointer, so the compiler leaves the value as it is rather than finalize it and leave the pointer dangling. An ordinary borrow of the same temporary does not keep it:

    fn mk(n i32) R {..}
fn id(r &R) &R {..}          // answers the borrow it is handed

imm p = id(&mk(2)) as *R;    // p may outlive the temporary: R's final never runs for it
imm q = id(&mk(3));          // an ordinary borrow: R's final runs at the end of this statement

    A value dies on the path that still holds it, and only there. Where a variable's value was moved out, or given, on only some of the paths that reach the end of its scope — in one branch of an if or a match, in a loop that may not run, before an early return or break — the compiler keeps a hidden flag beside the variable, set where its value arrives and cleared where it leaves, and the end of its scope finalizes it only when the flag says the value is still there. A variable whose every path agrees has no flag, and costs nothing for it.

    imm f = File.open(name);
if verbose {
  log.keep(f);      // f moves to the log on this path
}
                    // f is closed here only if verbose was false

    A value assigned over dies as it is replaced: the new value is evaluated first, then the old one is finalized, then the new one is stored. This is so for a variable, a field or an element of one, and a value reached through a reference (*r = v). Where the variable holds nothing to replace — it was never given a value, or its value moved out — nothing is finalized; where that depends on the path, its flag decides.

    A value allocated in a region is finalized when the region lets it go: when its single owner expires, or, for a counted region, its last owner. It dies as above, and only then is its memory freed, so a finalizer may still use everything its value owns. A value moved out of a region's object belongs to its new holder, which finalizes it; the object's memory is freed without finalizing what was moved out. Only the whole value moves: a field of it may not be moved out (move semantics), so no object dies partly moved out.

    A value typed as an enum is finalized as the variant it holds. An enum may define its own final, which runs for every variant, and a variant may define one too: the variant's finalizer runs first, then the enum's, then the finalizers of the variant's fields (the enum's common fields among them), then the owning references those fields hold are released — the more specific type before the more general, as with inheritance in other languages. An enum none of whose variants has anything to finalize, such as Option[i32], costs nothing when its value dies.

    A global variable lives until the program shuts down. Whatever it holds is then finalized by its module's finalizer, after the module's own final: a value whose type finalizes, a tuple or an array of them, or an owning reference, which is released (Dynamic initialization of global variables). A module has an initializer and a finalizer of its own too, described there.

    struct R {
  pub n i32;
  fn final(self &uni) { print <- "final "; print <- n; print <- "\n"; }
}
imm one R;
imm pair (R, R);
imm many Array[R, 2];
imm owned So[R];
fn @initpure init() {
  one = new R(1);
  pair = (new R(2), new R(3));
  many = [new R(4), new R(5)];
  owned = new So[R](6);
}

    After main returns, this prints final 1 through final 6, one to a line.

    Constructing in a region

    An allocation constructs its value the same way, in the region. new Rc[mut, Node](1) runs Node's initializer on the memory the region allocated, after the region's own initializer has filled its bookkeeping. One given a finished Node instead, new Rc[mut, Node](n), moves it in and runs no initializer:

    import stdio use *;
import libc;

struct Counted is RegionRef {
  owners usize;
  fn alloc(size usize) *u8 { libc.malloc(size); }
  fn init(self &new) {
    print <- "region init\n";
    *self = new Counted(1usize);
  }
  fn aliasRef(self &uni Counted) { owners = owners + 1usize; }
  fn dealiasRef(self &uni Counted) bool {
    owners = owners - 1usize;
    owners == 0usize;
  }
  fn free(self &uni Counted) {
    print <- "free\n";
    libc.free(self as *u8);
  }
}

struct Node {
  pub n i32;
  pub fn init(self &new, k i32) {
    print <- "node init\n";
    *self = new Node(n: k * 10);
  }
  fn final(self &uni) { print <- "node final "; print <- n; print <- "\n"; }
}

fn main() i32 {
  {
    imm a = new Counted[mut, Node](1);    // Node's initializer runs, on the region's memory
    print <- a.n;
    print <- "\n";
  }
  {
    imm done = new Node(5);
    imm b = new Counted[mut, Node](done); // a finished Node moves in: no initializer runs
    print <- "moved in\n";
  }
  0i32;
}

    The first block prints region init, node init, 10, node final 10 and free. The second prints node init (for new Node(5)), region init, moved in, node final 50 and free. The allocator is described in custom allocators.

    Freezing a list

    list.freeze() consumes the list and moves its block, shrunk to the elements it holds, into a So[Array[T]]: the elements are not copied, move types included, and the owner's death finalizes each of them once. A list that holds nothing makes a one-byte block, since the owner of an Array[T] always owns heap bytes (owned arrays).

    Owned Arrays

    The body of a run-time length is Array[T], the array type without a size. It has no size of its own, so it is held only through a reference that carries the count, and the slice is its borrow: &Array[T] is the slice, and &mut Array[T] the slice that changes its elements; the earlier spelling, &[]T, is refused. Every array reference is borrowed. There is no owning array reference: a managed reference is thin, virtual, or fat with the count of a dynamically sized body, str or Array[T], never an array reference. A slice of bytes, &Array[u8], and a borrow of the text body, &str, are the same pair of words and different types, and either converts to the other with as. What owns an array is one of these:

    • A fixed-size array, whose size is part of its type. It may be held in a variable or a field, or allocated in a region and reached by a thin reference whose type carries the size. Its contents follow the allocation after <-, and fill the array in the region's memory, with no array made elsewhere and copied in; an array already made is moved in from the parentheses: 
      imm grid = new Rc[mut, Array[i32, 4]] <- fill 0i32;      // grid's type: Rc[mut, Array[i32, 4]]
imm made = new Rc[mut, Array[i32, 4]](new Array[i32, 4] <- 1, 2, 3, 4);
    • An owner of Array[T], when the number of elements is chosen at runtime and never changes: So[Array[T]], Rc[Array[T]], Arc[Array[T]] or Gc[Array[T]], each a pointer and a count, one hop to the elements. It is allocated by copying the elements of a slice, as an owner of str is, so only where the elements copy; a list's freeze() moves its own into one instead, any element included. The owner has len, indexes (o[i]) and takes a borrowed range (&o[a..<b]) as a slice does, and is lent as the slice wherever a &Array[T] is wanted, a generic's element type inferred from it. Which of the three kinds of list it is comes from its permission: held writable (So[Array[T]], Rc[mut, Array[T]]) its elements change but its length does not; held imm (Rc[imm, Array[T]], Arc[imm, Array[T]]) nothing changes. A borrow of a fixed-size array, &Array[T, n], converts to the slice. 
      imm primes = new Array[i32, 4] <- 2, 3, 5, 7;
imm shared = new Rc[imm, Array[i32]](&primes);     // a copy: a pointer and a count
imm total = sum(shared);                           // lent as the &Array[i32] sum takes
imm frozen = list.freeze();                        // a List[T]'s block, moved into a So[Array[T]]
    • A collection, when the number of elements is chosen at runtime. An array whose whole length is decided at runtime, and which may grow or shrink, is exactly what a collection is: a List holds a pointer to its elements, how many there are, and how many it has room for. A list held in a local is used directly; one that several owners share is a managed reference to it: 
      imm names = new List[i32] <- 3;
imm shared = new Rc[mut, List[i32]](names);     // names is moved in; shared's type: Rc[mut, List[i32]]

    The length of a shared list lives once, in the list, where every owner sees the same count. A length carried in each copy of a reference could not stay in step when the list grows. Writing +[], as a type or an allocation, is an error that says this.

    Why a push waits for a borrow of an element

    A collection's elements sit in one block, and a push may move every one of them to a bigger block. So a borrow of an element (list[i], dict[key], s.view()) keeps a local collection loaned while it is used: it may be read, but a push waits for the borrow's last use. The compiler refuses the push that would leave the borrow dangling:

    mut list = List[i32].empty();
list.push(10);
list.push(20);
imm first = list[0usize];     // borrows list, read-only
imm n = list.len();           // fine: the list may be read
list.push(30);                // refused: first is used again below
print <- *first;

    Copying what is needed out before the push leaves no borrow to wait for (imm firstX = l[0usize].x; l.push(p);). A mutable borrow (&mut list[i], or list.viewMut(), a &mut Array[T] of every element, and a String's s.viewMut() of its bytes) is one more alias of the elements: until its last use the collection may still be read and written in place, but not reshaped, by a push, a clear or a pop.

    mut list = List[i32].empty();
list.push(10);
list.push(20);
imm e = &mut list[0usize];
imm n = list.len();           // fine: read while the mutable borrow is live
list.set(1usize, 5);          // fine: written in place
*e = 7;                       // the last use of e

    Each collection declares ShapeChanging (a provisional name), as does any type the compiler finds to be one from its methods, a struct wrapping a list included:

    struct Pt { pub x i32; pub y i32; }

struct Bag {
  items List[Pt];
  fn first(self &) &Pt { items[0usize]; }
  fn add(self &mut, p Pt) { items.push(p); }
}

fn g(bag &mut Bag) i32 {
  imm e = bag.first();
  bag.add(new Pt(5, 6));      // refused: e is used again below
  e.x;
}

    Reached through a shared path, a &mut List parameter say, the same path is frozen the same way, and a push, a clear or a pop through another reference to the same collection, or by a call that might make one, is refused while the borrow is still to be used (fn f(l &mut List[Pt], p Pt) i32 { imm e = l[0usize]; l.push(p); e.x; } is refused at the push, as is a cursor held across a push: mut it = dq.items(); dq.push(9); it.next();). The full rules, for locals, fields, and what a call could do, are those of borrowed references.

    Because they are all one size, allocated memory holding one variant can be given a value of a different variant instead, and a pool allocator can hand out and reclaim variants of one enum interchangeably.

    Finalizing

    A value typed as the enum is finalized at the end of its life as the variant it holds would be: the tag says which variant it is. An enum may declare its own finalizer, which runs for every variant, after the variant's own if it has one, and before the finalizers of the variant's fields:

    enum Resource {
	fn final(self &uni) {
		log("released");     // runs for every variant, after its own
	}
	struct File {
		pub handle Handle;
		fn final(self &uni) {
			close(handle);    // runs first, for a File
		}
	}
	struct Nothing {}
}

    An enum with nothing to finalize in any variant costs nothing: dropping an Option[i32] does no work, while dropping an Option[String] finalizes the string when it holds one. An owning reference a variant holds is released as the enum value dies, so the owner held in a Some is let go with its Option.

    Declining the padding

    Padding every variant to the largest costs memory, and whether to pay it for the convenience of a value is a choice only you can make. Write @unsized to decline it:

    enum @unsized Shape {
	pub kind i32;

	pub struct Dot;
	pub struct Polygon {pub points Array[Point, 64];}
}

    Each variant then occupies only what it needs, and the enum has no single size. So no value of it may be held — not in a variable, not in a parameter, not in a field — and it is reached only by reference:

    imm shape &Shape = &someDot;

    Notice how a reference to a variant coerced automatically into a reference to the enum. Everything else is unchanged: the tag is still in the value, a common field is still readable through the reference, matching still recovers the variant, and dispatch still works. What is given up is the value semantics — holding one in a variable, copying it, passing it by value, and swapping a variant in place.

    Most types that want this are graphs and trees, and those are usually better served by an open trait and structs that are-a it: once a type is reached by reference anyway, there is little left for a closed set to buy. So @unsized is for the case that is genuinely closed, wants exhaustive matching, and has variants whose sizes differ enough to matter.

    It binds what a binding does (What a match takes): a copy of plain data, a move of an owner, a reference into a borrowed value (imm n Ok = &mut r else ... gives an &mut i32); it may be mut; and the pattern names only the variant, taking its type arguments from the value. An else that falls through is an error. Since the else leaves, r is known to be the variant after the declaration, as after any branch that leaves.

    A binding gets what the variant holds. A variant declared as a type (SomeInt(i32);, see Variant forms) holds that type itself, so intval above is the i32, with no field to name: Some, Ok and Error are declared this way. Bound by value, it is a copy of the i32, or, when what it holds moves, a move of it out of the matched value, which is then finalized without it; a mut binding changes the copy and not the matched value. Bound through a reference (case imm n SomeInt on a reference to the enum), it is a reference of the same permission to what the variant holds, an &i32 here. A variant declared as a struct binds the struct, whose tag is never a visible field.

    A variant is a name of its enum (see Naming a variant), and a pattern names it bare with no use: the match already knows which enum the value belongs to. This is true of every pattern on a value — a case, a bound if or elif, and an is test — and it looks through a reference, so case imm c Circle on a &Shape names Shape.Circle.

    A pattern names only the variant. The matched value supplies the rest: the type arguments, and, where it is a reference, the kind of reference, its region and its permission. On a &imm Shape, case imm c Circle binds an &imm Circle; on a &mut Shape (a borrow made at the match), an &mut Circle; on an Rc[imm, Shape], an Rc[imm, Circle]; on a Shape, a Circle. A test with no binding, case Circle or s is Circle, asks only whether the value is that variant. A pattern may still be written as the reference, case imm c &Circle, which then checks that the matched value is one: it is an error where the value is no reference, or is in another region, or has a weaker permission than the pattern asks for. A managed reference is never spelled in a pattern, and the older +Rc-mut Circle is refused.

    A binding through a reference points into the variant, and follows the collection rule. Through a reference, c is a reference into the value's payload, and a change of variant would have it read the payload as the wrong type. It is a borrow into the enum, as an element is a borrow into a list (Borrowed references), so it is allowed through any reference, and refused only if something could change which variant the enum holds while c is still to be used:

    • the enum stored over whole (*s = Shape.Rect(1, 2, 3)) or swapped, through the same name or another;
    • a call handed the enum, or anything that could reach it, whose body (or what it calls) does either, or whose body the compiler cannot read.

    Writing a field within the variant is not a change, whether through c or through the enum's name, and neither is a field every variant has (s.kind = 9), nor reading the enum, nor a call that only reads it. The refusal is reported where c is used again, and names the change; a change after its last use is fine, which is how a state machine moves to its next state. A &mut borrow of a local made where it is matched is asked the same (match &mut s: the local is one more alias while the binding is used, Freezing access to the source of a borrow); a & one needs no question: the borrow freezes the local until the binding's last use, and a uni, imm or mut1 reference has no other name to change it. A value owned by an Rc is another owner of the same value: where no writer can store another variant through any owner (Rc[imm, Shape]), the binding is a copy of the owner, counted one more and let go as the arm ends, typed as the variant (Rc[imm, Circle]), and the variant is at its enum's address, so nothing moves. Where another owner could change which variant the value holds (Rc[mut, Shape], Rc[ro, Shape]), no loan stands for it and the narrowing is refused: bind the payload by copy, or match through a borrow of the value, which is followed. An is test binds nothing.

    fn grow(s &mut Shape) {
  match s {
    case mut c Circle {c.radius = 2;}   // Ok: nothing changes the variant while c is used
    else {}
  }
}
fn restart(s &mut Shape, t &mut Shape) i32 {
  match s {
    case mut c Circle {
      c.radius = 2;       // Ok: writing a field within the variant
      *t = Shape.Rect(1, 2, 3);   // Error: t may be another name for s, and c is used again
      c.radius;
    }
    else {0;}
  }
}
fn step(m &mut Machine) {
  match &mut m.state {
    case mut c Circle {
      c.radius = c.radius + 1;
      m.state = Shape.Rect(1, 2, 3);  // Ok: c is not used again
    }
    else {}
  }
}

    The matched value's enum is asked first. A bare name in a pattern means that enum's variant whenever the enum has one of that name, whatever the name means elsewhere in the module, so a use of another enum with a Red does not change what case is Red means on a Lamp. Only a name the enum has no variant of is looked up as any other name is. A qualified pattern, case is Colors.Red, is taken as written; and a variant named through its enum alone, case Colors.Red, means case is Colors.Red, as the variant bare does.

    The value supplies a generic variant's type arguments. On an Option[i32], case imm s Some means Some[i32]. Arguments may still be written where the name is in scope, as Some[i32] always is. Written on a variant that is in scope only because the matched enum has it, they are an error that says to drop them or to name the variant through its enum.

    A struct variant bound by value is the value the arm took, under its variant's name, not a second copy of it. The arm takes the matched value into a variable of its own (a move of one that owns, which consumes a matched place on the paths to that arm), and when the arm ends it is finalized once, as the variant it is. Moving the bound variable, or handing it back as the case's value, moves that value. A bound variable declared mut changes that value, not a matched place: assigning over it, or over one of its fields, finalizes what is replaced, and a value swapped out of it with <=> leaves what was swapped in to be finalized with it. As with a plain mut local, one moved out (on every path or only on some) and then assigned over holds the new value, which is finalized with the matched value. A match on a call holds the matched value itself for the whole match and finalizes it as the match ends, whichever case ran.

    The form of the value after = decides what the binding is (What a match takes). A variable, as above, is tested where it stands and only the block that binds takes from it: the integer is a copy, and an Option that holds something that moves (an Option[String]) is moved from, which consumes the variable on that path, while the else block still has it. A borrow, if imm integer Some = &maybeInt, binds an &i32 into the Option instead and takes nothing, and a call is a temporary the statement owns. The pattern names only the variant: it takes the type argument, and the reference kind of a borrow, from the value.

    Option References

    Option references are optimized so they take no more space than regular references. The None reference value is just a non-addressable address (typically, 0). (Memory describes references.)

    Fine-tuning

    What a match takes

    The form of the expression after match decides what the match does with it, and a bound if, if imm c Circle = s, reads its value the same way. (Borrowing and moving are explained in Moves in depth and Borrowed references in depth.)

    • A place — a variable, a field of one, a dereference, an element at a name or a literal, match r — is matched as the value it holds. Every test reads it where it stands and takes nothing, so a match that only tests moves no resource away, and r is whole after it. An arm that binds is the one that takes: the binding holds the payload by value, a copy of a copy type, or a move of one that owns, which consumes r on the paths that reach that arm. A mut binding changes what the arm took and never r.
    • A borrow — match &r, &imm r, &mut r, &uni r — binds a reference of that kind into r, which stays frozen to the match for as long as the bindings are used. That is how a match changes r: match &mut r.
    • Any other value — a call, match f() — is a temporary the match owns: it is made once, every pattern reads it, and it is finalized as the match ends.

    A binding takes only what it binds. Where the payload is plain data (a number, a borrowed reference, a struct of them), the arm copies it and the place is whole after the arm, even where the enum holds an owner in another variant. A bound if guard (case imm x Some if x > 0) reads its binding before the arm is chosen, so it takes nothing from the matched value at all, a place or a call's temporary alike: it sees a copy of plain data, and a payload that owns something through a read-only borrow of it. A guard that fails leaves the value whole for the cases after it, and the arm that runs is the one that takes.
